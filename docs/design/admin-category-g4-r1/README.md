# ชุดตรวจแบบสุดท้าย G4 · ระบบจัดการหมวดหมู่บ้านพัก

**รุ่น** G4-r1 · UID-010 · 11 พฤศจิกายน 2026  
**สถานะ** เจ้าของอนุมัติ G4-r1 แล้ว เก็บชุดไว้ก่อนส่งต่อ  
**ขอบเขต** หน้าจัดการหมวดบนเดสก์ท็อปและมือถือ ผลของการตั้งค่าบนหน้าแรก และขั้นตอนลบหมวดฉบับแก้

ชุดนี้รวมไวร์เฟรมและม็อกอัป r2 ที่รับแล้วเข้ากับแบบลบหมวดที่รับภายหลัง ปุ่ม **ลบหมวดหมู่** อยู่ข้าง **บันทึกหมวด** ในหน้าแก้หมวด บนมือถือแผงยืนยันเลื่อนจากด้านล่างเหนือฟอร์มเดิมและแสดงข้อผิดพลาดในแผงเดียวกัน

## สิ่งที่ทีมต้องยึดตามแบบ

| เรื่อง | กติกาที่ตกลง |
| --- | --- |
| ข้อมูลตั้งต้น | เจ็ดหมวดเดิมเริ่มด้วยรายชื่อบ้านว่าง ใช้รายการเดียวกับหมวดใหม่ แอดมินเลือกบ้านและจัดลำดับเอง บ้านหลังเดียวอยู่ได้หลายหมวด |
| เพิ่มและจัดบ้าน | ค้นแล้วกด **เพิ่ม** ที่แถวบ้าน บ้านเข้าฟอร์มและหายจากผลค้นหาของหมวดนั้นทันที การเอาบ้านออกต้องยืนยัน ทั้งสองรายการมีผลบนเว็บหลังบันทึกหมวดสำเร็จ |
| บันทึกและสลับงาน | ใช้ **บันทึกหมวด** หรือ **บันทึกลำดับ** ตามงานที่กำลังทำ ถ้ามีงานค้างให้เลือกบันทึก ทิ้งการแก้ไข หรือแก้ต่อเมื่อเปลี่ยนหมวดหรือเข้าออกโหมดจัดลำดับ |
| สื่อทางลัด | หมวดใหม่เริ่มที่ **ใช้ไอคอน** แอดมินเลือกไอคอนจริงหรือรูปเอง ทุกหมวดต้องมีสื่อก่อนบันทึก ไอคอนบนหน้าแรกไม่มีแผ่นพื้นหลัง |
| ทางลัดและแถวบ้าน | เปิดแยกกันได้และใช้ลำดับหมวดร่วมกัน หมวดว่างหรือปิดทั้งสองสวิตช์ถูกซ่อนจากหน้าแรก ลิงก์ตรงกลับหน้าแรก เมื่อทางลัดเกินแปดให้แสดงเจ็ดหมวดแรกกับ **หมวดอื่น ๆ** เป็นช่องท้าย |
| ลำดับบ้านที่ลูกค้าเห็น | แถวบ้านแสดงบ้านพร้อมแสดงสูงสุดแปดหลังตามลำดับแอดมิน ข้ามหลังที่ไม่พร้อมและเติมจากลำดับถัดไป **ดูทั้งหมด** ใช้รายชื่อของหมวดและลำดับที่แอดมินจัด |
| การลบหมวด | ยืนยันพร้อมชื่อหมวดก่อนลบถาวร เมื่อลบสำเร็จกลับรายการหมวดพร้อม Toast หมวดหายจากหน้าแรกและลิงก์เดิมกลับหน้าแรก บ้านพักและหมวดอื่นของแต่ละหลังยังอยู่ |

การใช้ปุ่มลบโดยตรงทำให้เข้าถึงได้จากหน้าแก้หมวดทันที การยืนยันยังแยกเป็นจังหวะชัดเจน แผงบนมือถือใช้รูปแบบเดียวกับการยืนยันเอาบ้านออกและแสดงฟอร์มเดิมอยู่ด้านหลัง เมื่อยกเลิกจะกลับไปแก้ต่อจากจุดเดิม

## ผลตรวจและประเด็นส่งต่อ

| รายการ | ผลในรอบนี้ |
| --- | --- |
| ภาพหลักและลิงก์ | ตรวจขนาดและความครบของภาพอ้างอิง 40 ภาพ พร้อมลิงก์ไปยังสเปคและต้นฉบับ |
| ลบหมวด | ตรวจใน Pencil แล้วว่าปุ่มลบอยู่ข้างบันทึกทั้งสองขนาด และมือถือใช้แผงด้านล่างทั้งตอนยืนยันและเมื่อเกิดข้อผิดพลาด |
| ทางลัดหน้าแรก | ตรวจใน Pencil แล้วว่ากรณีพอดีมีหมวดจริงแปดช่อง และกรณีเกินใช้ **หมวดอื่น ๆ** เป็นช่องท้ายทั้งสองขนาด |
| จอขนาดกลางและการเข้าถึง | ทดสอบจุดเปลี่ยนตามพื้นที่แถบจริงและชื่อหมวดยาว รวมถึงลำดับโฟกัส ชื่อปุ่มสำหรับโปรแกรมอ่านหน้าจอ การใช้แป้นพิมพ์ การประกาศ Toast และการลดการเคลื่อนไหวบนหน้าจอที่ใช้งานได้ |
| กติกาที่ต้องสรุปก่อนส่วนที่เกี่ยวข้องเริ่มพัฒนา | ชนิดและขนาดไฟล์รูป สัดส่วนและการครอป สิทธิ์ผู้ดูแล และแหล่งข้อมูลบ้านที่จะเชื่อมจริง [สเปค](../admin-category-management-interaction-spec.md#5-ประเด็นที่ยังต้องกำหนด) · [ประเด็นแหล่งข้อมูลบ้านพัก](../../decisions/open-decisions.yaml) |
| การทดสอบระบบ | ทดสอบการบันทึก การลบ การรักษาบ้านในหมวดอื่น การอัปเดตหน้าแรกและลิงก์ตรง รวมถึงการลากและปัดบนหน้าจอที่ใช้งานได้ |

วันที่ 11 พฤศจิกายน 2026 เจ้าของอนุมัติ **G4-r1 รวมแบบลบหมวดฉบับแก้** และให้เก็บชุดไว้ก่อน รายการภาพและสเปคใน [ไฟล์อ้างอิงรุ่นที่อนุมัติ](review-manifest.json) ใช้ข้อมูลชุดเดียวกับที่ส่งตรวจ สถานะการตรวจใน Task Brief เป็นข้อมูล ณ ตอนจัดชุด ส่วนผลอนุมัติล่าสุดอยู่ในหน้านี้ [ขั้นตอนตรวจรับ G4](../governance/05-design-workflow.md)
