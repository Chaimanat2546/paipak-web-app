# UID-010 ไวร์เฟรม r2 ระบบจัดการหมวดหมู่บ้านพัก

เจ้าของยืนยันเริ่มปรับไวร์เฟรมตาม Task Brief เมื่อ 11 พฤศจิกายน 2026 และให้ส่งเดสก์ท็อปก่อน รอบนี้ใช้โครงหน้าหลังบ้านและฟอนต์ Mitr จาก r1 เพื่อให้ตรวจขั้นตอนที่แก้ได้ในบริบทเดิม

**สถานะ** เจ้าของรับภาพฉบับแก้และปิดรอบไวร์เฟรม r2 เมื่อ 11 พฤศจิกายน 2026

## ข้อสรุปและรายละเอียดสำหรับตรวจ

- แก้หรือสร้างหมวดใช้ **บันทึกหมวด** ส่วนโหมดจัดลำดับใช้ **บันทึกลำดับ** การกดเพิ่มจากผลค้นหาหรือยืนยันเอาบ้านออกปรับรายการในฟอร์ม และมีผลต่อหน้าเว็บเมื่อบันทึกหมวดสำเร็จ
- เจ้าของอนุมัติการวางช่องจัดการสื่อด้านซ้ายและตัวเลือก **ใช้รูปภาพ** กับ **ใช้ไอคอน** แบบซ้อนด้านขวาตามภาพอ้างอิงในฟอร์มเดสก์ท็อป ประเภทไอคอนใช้ปุ่มเลือกหรือเปลี่ยน ส่วนประเภทรูปภาพใช้ช่องคลิกหรือลากวาง แถวหมวดทางซ้ายแสดงไอคอนหรือรูปของหมวด
- เจ้าของรับแบบหน้าต่างเลือกไอคอนเดสก์ท็อปเมื่อ 11 พฤศจิกายน 2026 ตารางแสดงรูปไอคอนในแต่ละช่องและใช้กรอบเน้นตัวที่เลือก ภาพตรวจใช้ตัวอย่าง 48 ไอคอน [ภาพที่ตรวจ](dsbGG.png)
- ใช้ตารางไอคอนและขั้นตอนกด **ใช้ไอคอนนี้** ที่รับแล้วเป็นต้นแบบสำหรับมือถือ ทั้งสองขนาดหน้าจอวาง **ใช้ไอคอน** เหนือ **ใช้รูปภาพ** และเริ่มหมวดใหม่ในประเภท **ใช้ไอคอน** ให้แอดมินเลือกไอคอนจริงเอง
- เจ้าของรับลำดับตัวเลือกและค่าเริ่มต้นของหมวดใหม่เมื่อ 11 พฤศจิกายน 2026 [ฟอร์มสร้างหมวดเดสก์ท็อป](c8HlOM.png) · [ฟอร์มสร้างหมวดมือถือ](yIGpV.png)
- รายการหมวด ชื่อบ้าน และรูปของหมวดบ้านแนะนำโดยทีมเป็นตัวอย่างเพื่อแสดงการจัดหมวดเอง เจ้าของเลือกให้เจ็ดหมวดเดิมเริ่มด้วยรายชื่อบ้านว่าง แอดมินจัดการได้เต็มรูปแบบ เลือกบ้านและจัดลำดับตั้งต้นเอง [รูปตัวอย่างจากชุดภาพที่พักในโปรเจกต์](../dsd-001/papaipak-ui-assets/uid-003/r3-category-editorial/villa-9-outside-1.webp)
- เจ้าของรับสถานะบันทึกไม่สำเร็จในฟอร์มเดสก์ท็อปเมื่อ 11 พฤศจิกายน 2026 และกำหนดให้ข้อความใช้เฟดเข้าและเฟดออก แอดมินใช้ปุ่ม **บันทึกหมวด** ในฟอร์มเมื่อพร้อม [ภาพข้อผิดพลาดทั่วไป](adVRz.png) · [ภาพข้อผิดพลาดที่ชื่อหมวด](awOOQ.png)

## ผลตรวจก่อนปิดรอบไวร์เฟรม

เทียบภาพที่ส่งตรวจและเฟรมใน Pencil กับ Task Brief แล้ว การเลือกสื่อ การค้นหาแล้วกดเพิ่มบ้าน และการแสดงทางลัดเมื่อพอดีหรือล้นแถวตรงกับกติกาที่ตกลงไว้ สถานะบันทึกไม่สำเร็จมีภาพเดสก์ท็อปพร้อมข้อมูลที่แก้ไว้ ส่วนมือถือใช้กติกาเดียวกันตามสเปค หลักฐานรอบนี้เป็นไวร์เฟรมและภาพนิ่ง การลาก การแตะเลือกตำแหน่ง การใช้แป้นพิมพ์ และการบันทึกจริงยังต้องทดสอบกับหน้าจอที่ใช้งานได้

เจ้าของเลือกให้ใช้กล่องถาม **บันทึก**, **ทิ้งการแก้ไข** หรือ **แก้ต่อ** เมื่อมีงานค้างทั้งตอนเข้าและออกจากโหมดจัดลำดับ ข้อสรุปนี้บันทึกไว้ในสเปค ส่วนภาพหน้าต่างยืนยันในชุด r2 แสดงตัวอย่างตอนสลับไปแก้หมวดอื่น

เจ้าของเลือกให้ซ่อนหมวดว่างจากทางลัด แถวบ้าน และ **หมวดอื่น ๆ** หากเปิดลิงก์ตรงของหมวดว่างให้พาไปหน้าแรก ภาพตัวอย่างหน้าแรกแสดงผลหลังซ่อนหมวดว่างแล้ว

ถ้าแอดมินปิดทั้งสองสวิตช์ของหมวดที่มีบ้าน ให้ซ่อนหมวดจากทั้งสามจุดบนหน้าแรก หากลูกค้าเปิดลิงก์ตรง ให้พาไปหน้าแรกเหมือนกรณีหมวดว่าง

ภาพหน้าแรกทั้งเดสก์ท็อปและมือถือแสดงไอคอนทางลัดโดยไม่มีแผ่นพื้นหลัง และภาพฟอร์มแสดง **กำลังบันทึก…** กับข้อความยืนยันเมื่อสำเร็จด้านบนของพื้นที่ทำงานตามที่เจ้าของเลือก

เจ้าของรับภาพทั้งสองส่วนและยืนยันปิดรอบไวร์เฟรม ชุดภาพนี้เป็นฐานสำหรับ [ข้อเสนอขอบเขตม็อกอัป](../admin-category-management-brief.md#9-ข้อเสนอขอบเขตม็อกอัป)

ถ้าอัปโหลดรูปทางลัดไม่สำเร็จ ให้แจ้งที่ช่องรูปแล้วให้เลือกไฟล์ใหม่จากช่องเดิม ข้อมูลที่แก้ไว้ยังอยู่ตามสเปค

แถวบ้านบนหน้าแรกข้ามบ้านที่ไม่พร้อมแสดง แล้วไล่บ้านพร้อมแสดงตามลำดับจนครบแปดหลัง หากมีไม่ถึงให้แสดงเท่าที่มี
