# กติกาการแสดงข้อมูลหน้ารายละเอียดบ้านพัก

UID-003 · Property Detail r1 · 9 พฤศจิกายน 2026 · สำหรับตรวจแบบและส่งต่อการพัฒนา

หน้าเดียวกันใช้กับบ้านทุกหลัง ภาพ ชื่อ ทำเล ความจุ และราคาเริ่มต้นช่วยให้ประเมินบ้านได้เร็ว ส่วนรายละเอียดห้อง กฎ และเงื่อนไขราคาอยู่ในส่วนที่อ่านต่อได้ เดสก์ท็อปใช้แกลเลอรีด้านบน รายละเอียดด้านซ้าย และแผงราคาอ้างอิงด้านขวา มือถือเรียงเนื้อหาคอลัมน์เดียว โดยวางราคาใกล้ข้อมูลหลัก แผงราคาในแบบนี้แสดงข้อมูลอย่างเดียว งานจอง ราคาเสนอจริง และสถานะวันว่างแยกเป็นงานถัดไป [UID-003](../../../../tasks/design/UID-003.md) · [ขอบเขต UX/UI](../../approved-ux-ui-scope.md)

## แหล่งข้อมูลและลำดับที่ใช้

| แค็ตตาล็อก Supabase | ค้นหา `listings` ตาม `property_id` และ `is_active` ประกอบ `listing_prices` และ `listing_facilities` แล้วส่งเป็น `listing` | ใช้เป็นหลักสำหรับรหัส ชื่อ โซน ห้องนอน ห้องน้ำ จำนวนผู้เข้าพักสูงสุด และราคาเริ่มต้น ข้อมูลที่แสดงใช้ผลจากตัวแปลงของแค็ตตาล็อก |
| Devil API | เซิร์ฟเวอร์ระบบเดิมเรียก `GET /api/getAccommodation.php?hid=<id>` ที่ Deville Central เมื่อพบบ้านในแค็ตตาล็อก รับรายละเอียดเป็น `unknown` แล้วใช้เฉพาะรูปแบบที่ตัวแปลงอ่านได้ | ใช้ฟิลด์รายละเอียดที่ตรวจพบ เช่น เวลาเข้าออก ที่ตั้ง สิ่งอำนวยความสะดวก ข้อความจาก Textbox รูปประกอบในข้อความ และลิงก์สื่อ |
| รายละเอียดที่รวมจากสองแหล่ง | ถ้าผลจาก Devil เป็นออบเจ็กต์ ระบบเดิมให้ค่าที่มีข้อมูลจากแค็ตตาล็อกทับคีย์เดียวกันในรายละเอียด ได้แก่ `h_moredetail`, `h_people_max`, `h_time_checkin`, `h_time_checkout` และ `h_extra` ถ้า Devil ใช้ไม่ได้ ยังมีค่าจากแค็ตตาล็อกเท่าที่หาได้ | คงลำดับแหล่งของข้อมูลที่มีความหมายตรงกัน ใช้ `listing.people` เป็นตัวเลขความจุหลักและเลี่ยงการแสดง `h_people_max` ซ้ำ ค่า `h_extra` ต้องตรวจที่มาแยก เพราะฟิลด์จากสองแหล่งอาจคนละความหมาย |
| แกลเลอรี | เซิร์ฟเวอร์หน้ารายละเอียดอ่าน `images` ด้วย `property_id` แล้วเลือกชุดภาพนำกับชุดรูปทั้งหมดแยกกัน | ใช้รูปจริงที่ผูกกับบ้านเดียวกัน ใช้ `image_zone`, `caption`, `cover_select` เมื่อมีข้อมูล ภาพประกอบใน Textbox อยู่กับเนื้อหาของส่วนนั้น |

## ฟิลด์ที่ใช้บนหน้า

| ส่วนบนหน้า | ฟิลด์และชนิดที่อ่านได้ | กติกาการแสดง |
| --- | --- | --- |
| ชื่อ รหัส และทำเล | `listing.title` เป็นข้อความ, `listing.id` เป็นรหัส, `listing.zoneLabel` เป็นป้ายโซน, `detail.location` หรือ `h_village` เป็นข้อความ, `detail.sea` เป็นข้อความหรือเลข, `sea_chk`, `distance`, `unit` พบในตัวอย่างสด | ใช้ชื่อแค็ตตาล็อกแล้วให้ขึ้นบรรทัดได้ ถ้าชื่อว่างใช้ `พูลวิลล่า` ตามด้วยรหัสบ้าน ใช้ที่อยู่ที่มีจริงหรือป้ายโซนที่อ่านรู้เรื่อง เก็บระยะพร้อมหน่วยจากต้นทาง ค่า `0` อย่างเดียวบอกสถานะติดทะเลไม่ได้ บ้านที่มีหลักฐานยืนยันว่าติดทะเลใช้ป้าย `ติดทะเล` ได้ |
| ข้อมูลหลัก | `listing.bedrooms`, `listing.bathrooms`, `listing.people` เป็นตัวเลขหลังแปลง และ `detail.h_people_max` เป็นเลขหรือข้อความ | ใช้ไอคอนคู่ตัวเลขกับป้าย `ห้องนอน` `ห้องน้ำ` `พักได้สูงสุด` แสดงแต่ค่าที่มีหลักฐาน ถ้าแค็ตตาล็อกขาดความจุ ใช้ `h_people_max` เมื่อยืนยันที่มาและอ่านเป็นจำนวนได้โดยไม่เดา ค่าศูนย์จากการแปลงช่องว่างหรือข้อมูลผิดรูปไม่ใช้แทนจำนวนจริง และไม่ใช้จำนวนห้องที่กล่าวในข้อความมาเติมโดยคาดเดา |
| สระว่ายน้ำ | `facilities.swimming_pool` เป็นธง, `facilities.swim_type` เป็นข้อความ, `h_swimmingpool` เป็นข้อความ | แสดงประเภทสระเมื่อธงยืนยันและรู้ประเภท เก็บขนาด ความลึก และรายละเอียดในส่วนสระตามต้นฉบับ หากรู้เพียงว่ามีสระให้ใช้ `สระว่ายน้ำ` เฉย ๆ ช่องว่างยังไม่ยืนยันว่าไม่มีสระ |
| เวลาเข้าพัก | `h_time_checkin`, `h_time_checkout` จาก Devil หรือค่าที่แค็ตตาล็อกทับ | ใช้แถว `เช็กอิน` และ `เช็กเอาต์` แยกกัน แสดง `HH:mm` เมื่อค่าตรงรูปแบบเวลาและแปลงได้โดยความหมายเดิม ถ้าเป็นข้อความเงื่อนไขให้คงข้อความ เมื่อขาดเวลาใดให้ซ่อนเฉพาะแถวนั้น |
| สิ่งอำนวยความสะดวก | `facilities` เป็นออบเจ็กต์ของธง ส่วน `listing.amenities` มาจาก `listing_facilities` | ใช้รายการชื่อกับไอคอนจากชุดชื่อที่รู้จัก ยอมรับค่าบวกตามตัวแปลงเดิม เช่น `true`, `1`, `y`, `yes`, `true` ในรูปข้อความ ถ้าชุด Devil ที่อ่านได้ว่าง ระบบเดิมใช้ชุดแค็ตตาล็อกแทน ตรวจความขัดแย้งก่อนรวมสองชุด และแสดงนโยบายสัตว์เลี้ยงแยกจากไอคอน |
| เกี่ยวกับบ้านพัก ห้องพัก ครัว และที่จอดรถ | `h_moredetail`, `h_bedroom_detail`, `h_kitchen_ware`, `h_parking` เป็นข้อความ | แยกตามฟิลด์โดยให้ `h_moredetail` ปรากฏครั้งเดียว ใช้รายการห้องได้เมื่อผู้เขียนแบ่งห้องไว้ชัดเจน ส่วนข้อมูลที่ปนหลายหัวข้อให้อยู่ในส่วนเดิม คงจำนวน ขนาด หน่วย และเงื่อนไขตามที่ให้มา |
| ราคาเริ่มต้น | `listing.price` เป็นตัวเลขที่ระบบเดิมแปลงเป็นราคาสาธารณะแล้ว หรือ `null` | ใช้ `เริ่มต้น ฿… / คืน` เฉพาะเมื่อมีจำนวนที่ใช้ได้ แผงขวาบนเดสก์ท็อปและบล็อกในลำดับอ่านบนมือถือใช้ข้อมูลเดียวกัน ถ้าไม่มีราคาให้ซ่อนตัวเลขและบล็อกเมื่อไม่มีข้อมูลอื่นที่ต้องแสดง |
| ค่าประกัน ค่าใช้จ่าย และราคาแยกตามวัน | `h_insurance`, `h_extra` เป็นเลขหรือข้อความ, `h_additional_costs`, `h_separate` เป็นข้อความ | แยกค่าประกันออกจากราคาต่อคืน แสดงค่าคนเสริมต่อเมื่อแหล่งข้อมูลยืนยันว่าเป็นค่าคนเสริม เก็บข้อความค่าบริการ โปรโมชัน และราคาแยกตามวันพร้อมเงื่อนไขเดิม ห้ามสรุปเป็นยอดจองหรือดึงราคาต่ำสุดจากข้อความ |
| กฎและสัตว์เลี้ยง | `h_rule`, `facilities.pet_detail` เป็นข้อความ | ให้หัวข้อแยกในส่วนเดียวกัน แสดงข้อจำกัดและข้อยกเว้นตามลำดับเดิม ค่าบวกของธงสัตว์เลี้ยงสื่อว่ามีข้อมูลรองรับเรื่องสัตว์เลี้ยง แต่คำอธิบายชนิด จำนวน น้ำหนัก และค่าใช้จ่ายยังขึ้นกับข้อความจริง |
| แผนที่และสถานที่ใกล้เคียง | `detail.map` เป็น URL, `travel[]` มี `travel_loca_name`, `travel_zone_name`, `travel_loca_url` | แสดงชื่อสถานที่ที่มีข้อมูล คงลำดับที่ได้รับ ใช้ลิงก์เฉพาะที่ตรวจรูปแบบแล้ว และเก็บชื่อเป็นข้อความหากขาดลิงก์ ไม่อนุมานระยะทางหรือเวลาเดินทาง |
| วิดีโอ | `h_videos` เป็นข้อความที่ตัวแปลงเดิมอ่าน URL ได้หลายรายการ | แสดงส่วนวิดีโอเมื่อมี URL ที่ใช้ได้ ฝังเฉพาะผู้ให้บริการและรูปแบบที่รองรับ URL อื่นที่อนุญาตแสดงเป็นลิงก์ได้ |

ตัวแปลงเดิมตัดช่องว่างรอบข้อความและยอมรับตัวเลขที่ใช้ได้จากฟิลด์ที่ระบุ ชุดสิ่งอำนวยความสะดวกใช้คีย์ที่รู้จักและแปลงชื่อเรียกซ้ำ เช่น `billiard` เป็น `billard` คอลัมน์ `insurance_fee`, `rating` และ `property_tags` ถูกเลือกในคิวรี แต่ไม่มีค่าที่ส่งต่อใน `listing` สำหรับส่วนเหล่านี้ พบ `h_alert` ที่มีข้อความเกี่ยวกับกฎในข้อมูลสด แต่ตัวแปลงหน้ารายละเอียดเดิมไม่เลือกฟิลด์นี้ จึงต้องยืนยันว่าข้อความใดเผยแพร่ให้ผู้เข้าพักได้ก่อนนำมาเป็นหัวข้อ `ข้อควรทราบ` แยกจาก `h_rule` ค่าเกี่ยวกับสมาชิก บัญชี ผู้ดูแล และข้อมูลจองอยู่นอกหน้ารายละเอียด รุ่นนี้ใช้ `h_insurance` สำหรับค่าประกันและใช้ `listing.price` โดยไม่คำนวณค่าคอมมิชชันซ้ำ [ประเภทข้อมูล](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/types.ts:36) · [คอลัมน์แค็ตตาล็อก](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/server.ts:106) · [การแปลงราคา](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/server.ts:292) · [ตัวแปลงรายละเอียด](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/detail.ts:489) · [ชื่อสิ่งอำนวยความสะดวก](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/amenities.ts:3) · [การทดสอบตัวแปลง](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/__tests__/detail.test.ts:37)

## ข้อความจาก Textbox

1. อ่านเป็นข้อความธรรมดาก่อน ตัดช่องว่างรอบฟิลด์ ทำให้ตัวแบ่งบรรทัดสม่ำเสมอ และคงบรรทัดว่างที่แบ่งย่อหน้า ระบบเดิมแยกตามบรรทัด ลบเครื่องหมายรายการบางแบบ และแสดงแต่ละบรรทัดเป็นรายการ แบบ r1 เก็บความต่างระหว่างย่อหน้า รายการ และหัวข้อย่อยให้ชัดขึ้น [ตัวแปลงบรรทัด](/C:/Users/chaym/Projects/baan-pool-villa/lib/villas/detail.ts:116) · [ตัวแสดงบรรทัด](/C:/Users/chaym/Projects/baan-pool-villa/components/villas/detail/detail-section-lines.tsx:125)
2. จัดเป็นรายการเมื่อมีเครื่องหมายขึ้นต้นชัดเจนหรือมีลำดับเลขที่ต่อเนื่อง เก็บลำดับเลขเมื่อเลขนั้นอ้างถึงข้ออื่นหรือหมายเลขห้อง ให้หัวข้อย่อยมีน้ำหนักต่างจากเนื้อความเฉพาะเมื่อผู้เขียนแยกหัวข้อไว้อย่างชัดเจน ประโยคต่อเนื่องหรือข้อความที่ใช้เครื่องหมายคละกันให้อ่านเป็นย่อหน้าตามต้นฉบับ
3. คงจำนวน หน่วย ช่วงเวลา ข้อยกเว้น และลำดับประโยค โดยเฉพาะกฎบ้าน ค่าประกัน ค่าไฟ โปรโมชัน และนโยบายสัตว์เลี้ยง หากข้อความเดียวรวมหลายเรื่อง ให้วางตามฟิลด์ต้นทาง หลีกเลี่ยงการแยกด้วยเครื่องหมายจุลภาค ขีด หรือทวิภาคโดยอัตโนมัติ การมีข้อความว่า `ห้อง 1` ใช้จัดย่อหน้าได้เมื่อแยกไว้ชัด แต่ใช้อนุมานจำนวนห้องทั้งหมดไม่ได้ เมื่อข้อความขัดกัน ให้คงถ้อยความทั้งสองไว้ในส่วนเดิม งดป้ายที่ฟันธง และส่งจุดขัดแย้งให้ผู้ดูแลข้อมูลตรวจ เช่น รายละเอียดเพิ่มเติมของ AB5 ระบุเรื่องสไลเดอร์ทั้งสองทาง [AB5](https://www.pmheevilla.com/villas/1353)
