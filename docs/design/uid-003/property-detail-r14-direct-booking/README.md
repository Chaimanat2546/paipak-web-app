# UID-003 · Property Detail r14 — จองบน papaipak

เจ้าของระบุว่าการจองอยู่ในระบบ papaipak ทั้งขั้นตอน แบบนี้ใช้แทนเส้นทางติดต่อแอดมินใน r12–r13 และวางปฏิทินบนหน้ารายละเอียดตามที่เลือกไว้ใน r13

| แบบใน Pencil | เฟรม | ภาพตรวจแบบ |
| --- | --- | --- |
| Desktop 1440 | `c9P4W` | [เต็มหน้า](desktop-full.png) |
| Mobile 390 | `yueTK` | [เต็มหน้า](mobile-full.png) |
| เลือกวัน ตรวจราคา และไปหน้าจอง | `LAPxi` | [สถานะการจอง](booking-states.png) |

1. ผู้ใช้ดูบ้านและปฏิทินได้ก่อนเข้าสู่ระบบ เลือกวันเช็กอินและเช็กเอาต์จากปฏิทิน ระบุจำนวนผู้เข้าพักรวม และระบุสัตว์เลี้ยงแยกตามนโยบายของบ้าน วันเช็กเอาต์ไม่คิดเป็นคืนพัก
2. ปุ่ม `ตรวจราคาและวันว่าง` พร้อมใช้เมื่อข้อมูลจองครบและถูกต้อง ระบบตรวจทั้งช่วงวัน ความจุและเงื่อนไขสัตว์เลี้ยง ราคาเริ่มต้นและราคาที่เห็นในปฏิทินใช้ประกอบการเลือก ยอดสำหรับการจองแสดงหลังได้ผลตรวจเท่านั้น
3. หากตรวจผ่าน ให้แสดงช่วงเข้าพัก จำนวนคน ยอดที่ตรวจแล้ว และปุ่ม `ไปหน้าจอง` การแก้วัน คน หรือสัตว์เลี้ยงต้องตรวจยอดใหม่ ถ้าช่วงวันไม่ว่างให้แก้วัน ถ้าระบบตรวจไม่ได้ให้ลองใหม่และเก็บค่าที่เลือกไว้
4. เมื่อกดไปหน้าจอง ให้ผู้ใช้ที่ยังไม่ได้เข้าสู่ระบบผ่าน Auth โดยคงบ้าน วัน จำนวนคน และสัตว์เลี้ยงระหว่างการใช้งานที่ต่อเนื่อง ถ้าปิด Auth ให้กลับหน้ารายละเอียดพร้อมค่าที่เลือก เมื่อเข้าสู่ระบบสำเร็จให้ตรวจราคาและวันว่างใหม่ก่อนเดินต่อ และให้ผู้ใช้ทบทวนหากยอดเปลี่ยน การรีโหลด ปิดแท็บ หรือหมดอายุเป็นไปตามกติกา Booking Intent ที่รับไว้ [UXD-001](../../uxd-001/edge-flows.md)

ตัวอย่างบนบอร์ดใช้ช่วง 24–26 ส.ค. 2569 พัก 2 คืน จำนวน 12 คน และยอดจำลอง ฿27,800 สำหรับตรวจหน้าตาของผลตรวจ ปฏิทินใช้ภาพข้อมูลย้อนหลังของ RimLay จาก r13 ผลตรวจราคาไม่ถือเป็นการจองสำเร็จหรือการกันห้อง ส่วนแหล่งยืนยันราคาและวันว่าง รวมถึงกติกาการกันห้อง ยังอยู่ใน `OPEN-007` และ `OPEN-006` [รายการที่ยังเปิด](../../../decisions/open-decisions.yaml)
