# กติกาข้อมูล Property Detail สำหรับตอนพัฒนา

UID-003 r27 · ข้อเสนอประกอบการตรวจแบบใน Pencil · งานออกแบบเท่านั้น

หน้าใช้โครงเดียวกันทั้ง 7 หมวด รายละเอียดในแต่ละส่วนขึ้นกับข้อมูลที่ยืนยันได้ของบ้านหลังนั้น ป้ายหมวด Home เป็นข้อมูลของ papaipak แยกจากป้ายข้อเท็จจริงในหน้า เช่น “ติดทะเล” “บ้านสองฝั่ง” หรือ “รับสุนัขและแมว”

| หมวด | สิ่งที่รองรับในหน้ารายละเอียด | สิ่งที่ใช้ตัดสินหมวด |
| --- | --- | --- |
| แนะนำ | ใช้ข้อมูลบ้านและรูปจริงเหมือนบ้านอื่น | รายการคัดสรรของ papaipak แถวเปิดใหม่ของต้นทางใช้เทียบตัวอย่างได้ |
| ใกล้ทะเล | รองรับติดทะเล ระยะที่มีหน่วย และระยะที่ไม่ยืนยัน | แยกเงื่อนไขติดทะเลกับระยะเดินทาง เกณฑ์ระยะต้องมาจาก papaipak |
| สายปาร์ตี้ | แยกอุปกรณ์ประจำบ้าน บริการเช่า และกฎใช้เสียงตามสถานที่และเวลา | อ่านกฎร่วมกับธงอุปกรณ์ ชื่ออุปกรณ์อย่างเดียวไม่ยืนยันว่าจัดปาร์ตี้ได้ |
| ราคาพิเศษ | แสดงโปรโมชัน โปรไฟลุก และโปรวันหยุดตามวันที่มีผล | ใช้ช่วงวันและราคาในข้อมูลปัจจุบัน แถวโปรเก่าไม่ยืนยันสิทธิ์จอง |
| Outing | ห้องแยกฝั่ง/ชั้น ที่จอดรถ จำนวนคนสูงสุด และรูปแบบเปิดห้องตามวัน | ใช้ความจุและเงื่อนไขเปิดห้องที่ยืนยันแล้วร่วมกับเกณฑ์หมวด |
| Pet Friendly | แสดงประเภท จำนวน น้ำหนัก ค่าใช้จ่าย และสิ่งที่ต้องเตรียมเท่าที่มี | ต้องยืนยันว่าอนุญาตและอ่านเงื่อนไข ไม่อาศัยธงที่ขัดกับข้อความ |
| Luxury | รองรับข้อมูลอ่างอาบน้ำ จากุซซี่ สระ และรายละเอียดห้อง | รายการคัดสรรของ papaipak อุปกรณ์ชิ้นเดียวไม่ยืนยันหมวด |

| ข้อมูลต้นทาง | สิ่งที่หน้าแสดง | ข้อที่ต้องคำนึงตอนทำโค้ด |
| --- | --- | --- |
| HTTP 200 แต่ `detailStatus` เป็น `unavailable` หรือ `missing_token` | คงชื่อ ทำเล ความจุ รูป และราคาอ้างอิงที่แค็ตตาล็อกยืนยัน บอกสั้น ๆ ว่ารายละเอียดบางส่วนยังไม่พร้อม | ตรวจสถานะใน payload แยกจาก HTTP และจากสถานะปฏิทิน แยกไม่มีข้อมูลออกจาก “ไม่มี” เมื่อทราบจริง `404` ของหน้าไม่มีบ้านไม่ใช่กรณีข้อมูลเสริมไม่พร้อม |
| ความลึกสระระบุหน่วยชัด | แสดงแยกสระหลัก สระเด็ก และแต่ละโซน รักษาช่วงและคำว่า “ประมาณ” | อ่านค่าตัวเลขเดี่ยวหรือช่วงพร้อมหน่วยเดียวกัน รองรับเลขไทย ช่องว่าง และหน่วย `ซม.`/`cm` กับ `ม.`/`m` แปลงเซนติเมตรเป็นเมตรเมื่อหน่วยต้นทางชัด เช่น Great Oasis `130–150 ซม.` → `1.30–1.50 ม.` และ 91 CLEAR `70 ซม.` → `0.70 ม.` |
| ค่าไม่สมเหตุผล หน่วยหาย หรือหลายหน่วยขัดกัน | เว้นช่องความลึกที่ยังยืนยันไม่ได้ คงข้อมูลชนิดสระ ขนาด และสไลเดอร์ที่ยืนยันแยกได้ | LYYA ส่ง `ลึก 120เมตร` ห้ามหาร 100 จากขนาดตัวเลขหรือเปลี่ยนหน่วยเอง เก็บค่าเดิม รหัสบ้าน โซนสระ และแหล่งที่มาไว้ให้ผู้ดูแลตรวจ แก้ที่ต้นทางหรือทำรายการแก้ที่มีหลักฐานและวันยืนยัน ถ้ายืนยันว่า 120 **ซม.** จึงแสดง `1.20 ม.` ตั้งช่วงที่ยอมรับได้แยกตามชนิดสระก่อนใช้งานจริง ตัวกรองในรายงานเป็นเพียงรายการให้ตรวจ ไม่ใช่เกณฑ์ตัดค่าจริง |
| ระยะถึงทะเล | แสดงคำว่า “ติดทะเล” เฉพาะเมื่อยืนยันจริง ถ้ารู้แค่ระยะให้แสดงเป็นระยะ | ตรวจความหมายของ `sea_chk`, `sea`, `distance`, `unit` และ `distanceToSea` ทีละแหล่ง ค่าว่างหรือ 0 ไม่ยืนยันว่าติดทะเล ไม่ผสมค่าต่างหน่วย และไม่ใช้ป้ายทำเลแทนระยะ |
| ราคาเริ่มต้นว่าง / ราคาขึ้นกับวันหรือจำนวนห้อง | ใช้ “ยังไม่ระบุราคาเริ่มต้น” แต่ยังดูปฏิทินได้ แยกจำนวนคนตามราคาออกจากจำนวนสูงสุด | เก็บ 0, null และค่าราคาที่ตรวจแล้วแยกกัน ห้ามเอาราคาวันหนึ่งหรือค่าจากเดือนก่อนมาเป็นราคาเริ่มต้นเอง Great Oasis มีแพ็กเกจเปิด 5/8/10 ห้องตามวันและข้อความราคา/ความจุจากหลายฟิลด์ ต้องตรวจเงื่อนไขจริงก่อนเปิดให้เลือกแพ็กเกจหรือเสนอราคา |
| ห้องนอนและบ้านหลายฝั่ง | ใช้กลุ่มฝั่ง/ชั้น/โซนเมื่อแหล่งข้อมูลแยกไว้ และเก็บรายละเอียดห้องน้ำร่วม เตียง และฟูก | อย่าทำสำเนารายละเอียดอีกฝั่งถ้าต้นทางไม่ได้ระบุว่าเหมือนกัน หากนับห้องจากข้อความแล้วขัดกับค่ารวม ให้แจ้งตรวจ ไม่แอบแก้ยอดรวม |
| ค่าประกัน ค่าคนเพิ่ม และค่าใช้จ่าย | แยกรายการพร้อมฐานคิด เช่น ต่อครั้ง ต่อตัว ต่อคืน หรือคิดเมื่อเข้าเงื่อนไข | `h_extra` อาจถูกเติมจากจำนวนเตียงเสริม จึงห้ามใช้เป็นค่าคนเพิ่มเมื่อไม่มีที่มาและหน่วยชัดเจน อย่าดึงเลขจากข้อความเงื่อนไขแล้วทิ้งหน่วยหรือช่วงราคา |
| นโยบายสัตว์เลี้ยง | วางเงื่อนไขใกล้ช่องจำนวนสัตว์เลี้ยงและในรายละเอียด เช่น น้ำหนัก จำนวน ประเภท ค่าบริการ ของที่ต้องเตรียม | ใช้สถานะอนุญาต / ไม่อนุญาต / ยังไม่ยืนยัน แยก `facilities.pets` จาก `facilities.pet_detail` และให้ตรวจเมื่อขัดกัน แสดงค่าที่ระบุจริงเท่านั้น เช่น In2 มี ฿300/฿500 ตามน้ำหนักแต่ไม่ระบุรอบการคิดค่า |
| อุปกรณ์และกฎเรื่องเสียง | แยกอุปกรณ์ที่มีในบ้าน อุปกรณ์เช่า และข้อจำกัดตามเวลา เช่น 91 CLEAR ใช้เสียงนอกบ้านถึง 22:00 น. | มีคาราโอเกะไม่เท่ากับอนุญาตเสียงดังทั้งคืน Prime Asia ไม่มีคาราโอเกะประจำบ้าน แต่ต้นทางมีบริการเช่าที่ขึ้นกับคิว เก็บเป็นเงื่อนไขบริการเสริม อย่าสร้างแท็กว่ามีอุปกรณ์ฟรี |
| ข้อความยาวหรือมีรูปแทรก | ยุบตามหัวข้อ แสดงข้อสำคัญก่อน ขยายเพื่ออ่านครบ ซ่อนหัวข้อและแท็บที่ไม่มีข้อมูล | รักษาลำดับหัวข้อ ย่อหน้า รายการ หน่วย เงื่อนไข และสื่อในกลุ่มที่ถูกต้อง ห้ามแสดง HTML ดิบ สกัดเฉพาะรูป/วิดีโอจากแหล่งที่อนุญาต ใช้การยุบ/ขยายที่คีย์บอร์ดเข้าถึงได้ |
| แกลเลอรี 0/1/หลายรูป | 0 รูป: แถบสั้นเมื่อยืนยันว่าไม่มี; 1 รูป: ใช้รูปเดียวไม่ใส่ลูกศรหรือช่องซ้ำ; หลายรูป: ใช้แกลเลอรีร่วม แยกรูปรีวิว | แยกยืนยันไม่มีรูปออกจากกำลังโหลด/โหลดไม่สำเร็จ `?view=card` เป็นรายการรูปตัวอย่างสำหรับการ์ด ห้ามใช้จำนวนนั้นเป็นยอดแกลเลอรีเต็ม ตรวจรูปซ้ำ ลิงก์เสีย และกู้โฟกัสเมื่อปิดตัวดูรูป |

ตัวอย่างที่ควรใช้ตรวจตัวแปลง: [DV-1158](https://www.pmheevilla.com/api/villas/1158) ระบุสระหลัก 160 ม. และสระเด็ก 70–90 ม. แยกเป็นสองรายการให้ตรวจ ส่วน [DV-1507](https://www.pmheevilla.com/api/villas/1507) มีทั้ง 80 เมตรและ 1.8 ม. อยู่ในข้อความเดียวกัน จึงไม่เลือกแสดงตัวเลขใดเป็นความลึกรวมเอง เมื่อผู้ดูแลยืนยันแล้ว ให้บันทึกค่าเริ่ม/ปลาย หน่วย ประเภทสระ แหล่งยืนยัน และวันแก้ เพื่อให้ตรวจย้อนกลับได้

ปฏิทินเป็นส่วนหนึ่งของหน้า Desktop และมือถือ ใช้กริดเดิมและสัญลักษณ์ร่วม สีใช้ช่วยอ่าน มีชื่อสถานะสำหรับเทคโนโลยีช่วยอ่านโดยไม่ต้องยัดคำลงทุกช่อง

| สถานะต้นทาง | วิธีแสดงและกติกา |
| --- | --- |
| `base` / `holiday` | ราคาตามวันที่มีข้อมูล ถ้าอ่านสถานะได้แต่ยังไม่มีราคาที่ใช้ได้ ให้บอกว่าไม่มีราคาและไม่แสดง ฿0 |
| `promotion` / `hotpro` / `hot_holiday` | ใช้ป้ายโปรหรือไอคอนไฟตามชนิดจริง วันหยุดที่มีโปรต้องสื่อได้ทั้งสองอย่าง แสดงเฉพาะวันที่ใช้ได้ตามปฏิทินปัจจุบัน |
| `booking_confirmed` / `booking_waiting` | ปิดการเลือกทั้งคู่ แสดง “ติดจอง” กับ “รอยืนยัน” แยกกัน ไม่แสดงราคาที่ค้างในข้อมูลดิบ |
| วันผ่านไปแล้ว | ปิดการเลือกด้วยวันท้องถิ่น Asia/Bangkok คงสัญญาณติดจองที่ต้นทางยืนยันไว้ |
| กำลังโหลด / 429 / 502 / 503 | คงกรอบเดือนไว้ แยกโหลดจากอ่านไม่ได้ ให้ลองใหม่หลังเวลาที่ต้นทางระบุสำหรับ 429 ไม่ระบายทั้งเดือนว่าเต็ม |

การกดตรวจราคาและวันว่างต้องตรวจช่วงวันและราคาจากระบบจองของ papaipak ใหม่ ไม่ใช้ค่าภาพหรือข้อมูลอ้างอิงเป็นราคายืนยัน คืนเข้าพักนับแบบรวมวันเข้าและไม่รวมวันออก ต้องแยกกติกาการเลือกวันออกจากกติกาวันที่ค้างคืน ตรวจจำนวนคนรวมและสัตว์เลี้ยงตามเงื่อนไขบ้าน ปฏิทินที่โหลดสำเร็จไม่ได้ยืนยันว่าจองได้แล้ว การล็อกห้อง ระยะเวลาล็อก และแหล่งราคาจริงยังอยู่ใน OPEN-006/OPEN-007 ของโครงการ
