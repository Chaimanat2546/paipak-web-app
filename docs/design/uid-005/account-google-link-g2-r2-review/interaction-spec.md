# เชื่อม Google จากหน้าความปลอดภัย · การใช้งาน G2-r2

UID-005 · รอภูตรวจรับ

ภูชี้แจงว่า **“ครั้งแรกก็ไม่ใช้”** ในการสนทนาเรื่องการยืนยันเพิ่มของ papaipak แบบรอบนี้ใช้เซสชันปัจจุบันของสมาชิกที่เปิดหน้าความปลอดภัย และกด **เชื่อม Google** เพื่อเปิดหน้าเลือกบัญชีของ Google ได้โดยตรง

| ขั้น | สิ่งที่แสดงและทางเดิน |
| --- | --- |
| เริ่มเชื่อม | เปิดจากหน้าความปลอดภัยของสมาชิกที่เข้าสู่ระบบอยู่ แสดงปุ่ม **เชื่อม Google** ในแถว Google เมื่อบัญชียังไม่ได้เชื่อม กดแล้วไปยังหน้าเลือกบัญชีของ Google |
| ระหว่างเปิดหน้า Google | หากการเปิดหน้าใช้เวลา แสดงกำลังเปิด Google และพักปุ่มกดซ้ำ |
| ตรวจและยืนยันการเชื่อม | เมื่อได้รับบัญชี Google ที่เลือกแล้ว แสดงบัญชี papaipak ปัจจุบันและบัญชี Google ที่จะเชื่อม ให้เลือก **ยืนยันการเชื่อม** หรือ **ยกเลิก** ขั้นนี้ยืนยันความตั้งใจและบัญชีที่จะเชื่อม |
| รอผลและสำเร็จ | หลังกดยืนยัน แสดงกำลังเชื่อมและพักการกดซ้ำ เมื่อมีผลยืนยันสำเร็จจึงกลับหน้าความปลอดภัยพร้อมสถานะ **เชื่อมบัญชีแล้ว** |
| ใช้บัญชีที่เลือกไม่ได้ | แจ้งผลและเปิดทาง **เลือกบัญชี Google อื่น** |
| เชื่อมไม่สำเร็จ | ใช้ **ลองเชื่อมอีกครั้ง** เมื่อยืนยันผลล้มเหลวแล้ว หากยังไม่ทราบผลให้ตรวจคำขอเดิมก่อนแสดงผลหรือเปิดให้ส่งซ้ำ |
| ยกเลิกหรือเซสชันหมดอายุ | ยกเลิกที่ Google หรือจากหน้าตรวจบัญชีให้กลับหน้าความปลอดภัยด้วยสถานะการเชื่อมเดิม ถ้าเซสชันหมดอายุให้ใช้เส้นทางเข้าสู่ระบบและเริ่มรายการใหม่จากบัญชีที่ยืนยันแล้ว [สถานะเซสชัน](../g2-r8-review/README.md) |

การเข้าสู่ระบบด้วย Google ใช้ [มติ Google Login เดิม](../../dsd-001/home-auth-google-no-extra-email-verification.json) สำหรับเส้นทางจากหน้าเข้าสู่ระบบเมื่ออีเมลตรงกับบัญชี papaipak เดิมที่ยังไม่ได้เชื่อม ให้ดู [Home Auth Google Link G2-r41](../../dsd-001/home-auth-google-link-g2-r41/README.md)

แบบนี้ใช้ตัวอย่างอีเมลเดียวกันเพื่อแสดงการตรวจบัญชีทั้งสอง เกณฑ์เมื่ออีเมลต่างกัน การตรวจสถานะเซสชันและผลการเชื่อม และการใช้งานจริงกับ Google ยังต้องสรุปหรือทดสอบในระบบ
