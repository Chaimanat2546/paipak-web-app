# โปรไฟล์ลูกค้า · ข้อกำหนดการใช้งาน G2-r1

สถานะรอภูตรวจรับ · ขอบเขตตาม [G0 แผนรอบ 1](owner-g0-approval.json)

## การเข้าหน้าและการแก้ข้อมูล

- สมาชิกเปิด **ข้อมูลส่วนตัว** จากเมนูบัญชีเพื่อดูข้อมูลของตนเอง ผู้ที่เปิดหน้าจากลิงก์โดยไม่มีเซสชันที่ใช้ได้จะเข้าสู่ขั้นตอน Auth ที่อนุมัติแล้ว เมื่อสำเร็จจึงกลับมาเปิดโปรไฟล์และโหลดข้อมูลบัญชีของตนเอง
- **แก้ไขข้อมูล** เปิดฟอร์มแทนข้อมูลในหน้าเดิมและย้ายโฟกัสไปที่ชื่อผู้ใช้ **ยกเลิก** ทิ้งค่าที่แก้ในรอบนั้น กลับไปแสดงค่าที่บันทึกไว้ และคืนโฟกัสไปที่ **แก้ไขข้อมูล**
- เดสก์ท็อปวางเมนูซ้ายและเนื้อหาขวา มือถือวางเมนูเหนือเนื้อหาและเรียงปุ่มบันทึกกับยกเลิกลงมา ลำดับข้อมูลเหมือนกันทั้งสองขนาดจอ

| ส่วนประกอบ | ดู | แก้ไข |
| --- | --- | --- |
| ชื่อผู้ใช้ | แสดงค่าที่บันทึกไว้ หรือ “ยังไม่ได้ตั้งชื่อผู้ใช้” | แก้หรือเพิ่มได้ เป็นชื่อแสดงผล ตัวอักษรอังกฤษ A–Z, a–z และตัวเลข 0–9 จำนวน 3–20 ตัว |
| เบอร์โทร | แสดงเบอร์ที่บันทึกไว้ หรือ “ยังไม่ได้เพิ่มเบอร์โทร” | บัญชีที่ยังไม่มีเบอร์เห็นตัวเลือกประเทศกับช่องกรอกเบอร์ เบอร์ที่มีอยู่แล้วแสดงเป็นข้อความ |
| อีเมลบัญชี | แสดงอีเมลที่บันทึกไว้ | แสดงเป็นข้อความ |

การตั้งไทย +66 เป็นค่าเริ่มต้นในภาพเป็นข้อเสนอสำหรับ Wireframe อ้างอิงรูปแบบจากฟอร์มสมัครสมาชิก ข้อมูลทุกชุดในภาพเป็นตัวอย่าง

## ผลการบันทึก

| สถานะ | การแสดงผลและการใช้งาน |
| --- | --- |
| ข้อมูลในช่องผิด | แสดงข้อความอธิบายใต้ช่องที่ผิดพร้อมค่าที่กรอกไว้ ใช้ข้อความกับเส้นขอบ เมื่อกดบันทึกแล้วพบข้อผิดพลาดให้ย้ายโฟกัสไปช่องแรกที่ต้องแก้ |
| กำลังบันทึก | คงค่าที่กรอกไว้ แสดง “กำลังบันทึก…” และพักการส่งซ้ำ การแก้ช่อง และการกดยกเลิกในฟอร์ม ระหว่างรอผลคำขอ |
| บันทึกสำเร็จ | เมื่อระบบยืนยันผลแล้วจึงกลับโหมดดู แสดงค่าที่บันทึกแล้วและข้อความ “บันทึกข้อมูลเรียบร้อยแล้ว” บนหน้าเดิม |
| ยืนยันว่าบันทึกไม่สำเร็จ | อยู่โหมดแก้ไข เก็บค่าที่กรอกไว้ แสดงข้อความใกล้ปุ่มบันทึก และให้ลองใหม่ได้เมื่อระบบยืนยันว่าคำขอเดิมไม่สำเร็จ |

เส้นทางคีย์บอร์ดในฟอร์มเรียงจากชื่อผู้ใช้ ไปที่ตัวเลือกประเทศและช่องเบอร์เมื่อแสดงช่องเหล่านี้ แล้วไป **บันทึกข้อมูล** และ **ยกเลิก** ข้อความผิดพลาดผูกกับช่องที่เกี่ยวข้อง ส่วนข้อความกำลังบันทึกและผลลัพธ์ควรประกาศให้โปรแกรมอ่านหน้าจอทราบ หลังบันทึกสำเร็จให้ย้ายโฟกัสไปที่หัวข้อ **ข้อมูลส่วนตัว**

## เกณฑ์ที่ใช้ตรวจ

- G2-01 โหมดดูและโหมดแก้ไขอ่านได้ทั้งสองขนาดจอ และใช้ Modern Split ตาม PAGE-009
- G2-02 บัญชีที่มีเบอร์แสดงเบอร์และอีเมลเป็นข้อความในโหมดแก้ไข ส่วนบัญชี Google ที่ข้อมูลขาดแสดงข้อมูลที่ขาดตามจริงและมีช่องเพิ่มข้อมูล
- G2-03 กำลังบันทึก สำเร็จ ผิดรูปแบบ และบันทึกไม่สำเร็จแสดงต่างกันชัดเจน มีตัวอย่างที่ค่าร่างยังอยู่หลังพบข้อผิดพลาด
- G2-04 ทางเข้าหน้า การกลับหลัง Auth และลำดับโฟกัสมีคำอธิบายประกอบ

## ประเด็นสำหรับสัญญาการทำงานจริง

รายการประเทศ กฎตรวจและแปลงเบอร์ การตรวจเบอร์ซ้ำ เงื่อนไขที่เบอร์ใหม่จะใช้เข้าสู่ระบบได้ การจัดการกรณีไม่ทราบผลการบันทึก และการเก็บค่าร่างข้ามการออกจากหน้าหรือโหลดใหม่ ยังรอกำหนดในการออกแบบพฤติกรรมระบบ การตรวจรอบนี้เป็นการตรวจ Wireframe และข้อกำหนด คีย์บอร์ด โปรแกรมอ่านหน้าจอ การยืนยันสิทธิ์ และการบันทึกจริงยังรอทดสอบในระบบ
