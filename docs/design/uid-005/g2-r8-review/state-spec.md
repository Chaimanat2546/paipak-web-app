# โปรไฟล์ลูกค้า · การเปลี่ยนสถานะ G2-r8

ชุดนี้เสนอการใช้งานทั้งหน้าสำหรับตรวจรับใน Pencil สิทธิ์ข้อมูลและโครงหน้าจาก [G2-r7](../g2-r7-review/README.md) และ [ขอบเขตข้อมูลสำหรับจอง](../g2-r2-review/interaction-spec.md) ใช้ประกอบกัน

| ช่วง | สถานะและทางไปต่อ |
| --- | --- |
| เปิดหน้า | ตรวจว่ามีเซสชันใช้ได้ก่อนแสดงข้อมูล ถ้าเปิดลิงก์ตรงโดยยังไม่ได้เข้าสู่ระบบ ให้แสดงปุ่มเข้าสู่ระบบเพื่อเปิด Auth ตามแบบเดิม ถ้าเซสชันหมดอายุ ให้ขอเข้าสู่ระบบอีกครั้ง เมื่อผ่านจึงเปิดโปรไฟล์และโหลดข้อมูลของบัญชีที่เข้าสู่ระบบ |
| โหลดข้อมูล | ใช้โครงกำลังโหลดจนได้ผล หากโหลดไม่สำเร็จให้ลองโหลดอีกครั้ง หลังได้ผลจึงแสดงค่าที่มีและแสดง “ยังไม่ได้ระบุ” เฉพาะช่องที่ขาด |
| โหลดรูป | รูปที่พร้อมแสดงใช้พื้นที่เดิม ระหว่างโหลดใช้โครงรูป หากยังไม่มีรูปหรือโหลดไม่ได้ให้ใช้อักษรย่อจากข้อมูลที่บันทึกไว้ หรือไอคอนสมาชิกเมื่อยังไม่มีอักษรย่อ ฟอร์มและข้อมูลอยู่ในตำแหน่งเดิม รูปเป็นส่วนแสดงผล |
| เข้าโหมดแก้ไข | ใส่ค่าปัจจุบันและย้ายโฟกัสไปชื่อจริง ฟอร์มที่ยังไม่มีการเปลี่ยนแปลงเสนอให้พักปุ่มบันทึก เมื่อมีการเปลี่ยนแปลงจึงเข้าสู่สถานะพร้อมบันทึก |
| กรอกข้อมูล | ชื่อผู้ใช้ที่อยู่ในฟอร์มใช้ตัวอักษรอังกฤษและตัวเลข 3–20 ตัว บัญชีที่ไม่มีเบอร์มีตัวเลือกประเทศ กรณีกรอกเบอร์ผิดให้แสดงคำอธิบายใต้ช่องและเก็บค่าที่พิมพ์ไว้ เมื่อส่งแล้วพบข้อผิดพลาดให้โฟกัสช่องแรกที่ต้องแก้ |
| เปิดตัวเลือกประเทศ | แสดงตัวเลือกใต้ช่องเบอร์ การเลือกเปลี่ยนรหัสประเทศและคงอยู่ในโหมดแก้ไข กด Escape เพื่อปิดและคืนโฟกัสที่ตัวเลือก ภาพใช้ไทยและ United States เป็นตัวอย่าง รายชื่อประเทศครบชุดและกฎเบอร์โทรรอสรุป |
| กดบันทึก | แสดงกำลังบันทึก คงค่าในฟอร์ม และพักการส่งซ้ำ เมื่อยืนยันผลสำเร็จจึงกลับโหมดดูและแสดงค่าที่บันทึกแล้ว เมื่อยืนยันว่าล้มเหลวให้คงร่างและลองใหม่ได้ |
| ผลบันทึกยังไม่ยืนยัน | เช่น การเชื่อมต่อขาดหลังส่งคำขอ ให้คงร่างและเสนอให้ตรวจผลคำขอเดิม เมื่อกดตรวจให้แสดงกำลังตรวจสอบผลและพักการกดซ้ำ ผลที่ยืนยันได้พาไปสถานะสำเร็จหรือล้มเหลว หากยังตรวจไม่ได้ให้กลับสถานะรอตรวจผล การตรวจผลเป็นการอ่านผลของคำขอเดิม |
| ยกเลิกหรือออกจากหน้า | **ยกเลิก** กลับโหมดดูและแสดงค่าที่เคยบันทึกไว้ ตามกติกาเดิม เมื่อกดลิงก์ไปหน้าอื่นในเว็บขณะมีค่าที่แก้ เสนอให้เลือก **แก้ไขต่อ** หรือ **ออกจากหน้า** ก่อนย้ายหน้า ระหว่างที่กล่องเปิดให้โฟกัสที่ตัวเลือกแก้ไขต่อ และคืนโฟกัสไปจุดเดิมเมื่อปิด |
| กลับมาเปิดโปรไฟล์ | หลังโหลดหน้าใหม่หรือเข้าสู่ระบบอีกครั้ง ให้อ้างอิงข้อมูลของบัญชีที่ยืนยันได้ กติกาเก็บร่างข้ามหน้า การแจ้งก่อนปิดแท็บ และการกู้ร่างหลังหมดเซสชันยังรอสรุป |
| ใช้ข้อมูลจอง | ใช้ข้อมูลบัญชีที่มีเพื่อกรอกล่วงหน้าและขอเฉพาะข้อมูลที่ขาดเมื่อจะจอง กฎว่าช่องใดต้องมีในกรณีจองต่าง ๆ ยังอยู่ในสัญญาการทำงานของ Checkout |

## สิ่งที่ขอให้ภูตรวจในรอบนี้

- พักปุ่มบันทึกเมื่อค่าทั้งหมดตรงกับข้อมูลที่บันทึกแล้ว
- ใช้ทาง **ตรวจสอบผล** เมื่อยังสรุปผลการบันทึกไม่ได้
- ถามก่อนออกไปหน้าอื่นในเว็บเมื่อมีข้อมูลที่แก้ไว้

การตรวจผลเมื่อหลุดหลังส่งเป็นแนวทางเสนอสำหรับ Profile โดยอาศัยหลักการตรวจคำขอเดิมจาก [ข้อกำหนด Auth ERR-01](../../dsd-001/home-auth-desktop-system-requirements.md) วิธีตรวจจริง ข้อขัดแย้งเมื่อข้อมูลถูกเปลี่ยนจากอีกแท็บ การยืนยันข้อมูลบัญชี และการใช้งานคีย์บอร์ดหรือเทคโนโลยีช่วยอ่านยังรอออกแบบสัญญาระบบและทดสอบในระบบ

## จุดตรวจรับ

- หน้าขอเข้าสู่ระบบ หน้าหมดเซสชัน และหน้าโหลดไม่สำเร็จมีทางไปต่อและไม่แสดงค่าของสมาชิกเดิม
- ภาพโทรศัพท์ผิดมีข้อความใต้ช่อง ภาพรอตรวจผลมีค่าที่ผู้ใช้กรอกอยู่ และใช้ปุ่มตรวจผล
- รูปอยู่ในขอบเขตแสดงผล ทุกสถานะมีภาพแทนที่อ่านได้ทั้งสองขนาด
- ตัวอย่างครอบคลุม 9 สถานะเพิ่มเติมบนเดสก์ท็อปและมือถือ ส่วนสถานะที่ใช้ร่วมกับ G2-r7 เปิดตรวจได้จากทะเบียนภาพ
