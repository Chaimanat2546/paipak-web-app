# การเข้าสู่ระบบและความปลอดภัย · ข้อกำหนด G2-r1

UID-005 · รอภูตรวจรับ · [ขอบเขต G0 ที่อนุมัติ](owner-g0-approval.json)

## ทางเข้าจากบัญชี

เมนูบัญชี **การเข้าสู่ระบบ** เปิดหน้า **การเข้าสู่ระบบและความปลอดภัย** แสดงสถานะของรหัสผ่าน อีเมลบัญชี เบอร์โทร และ Google ตามบัญชีจริง บัญชีที่มีรหัสผ่านจะเห็นปุ่มเปลี่ยนรหัสผ่าน ส่วนสถานะ Google แสดงผลการเชื่อมบัญชีได้ทั้งกรณีมีและยังไม่มีการเชื่อม บัญชีที่ใช้หลายวิธีแสดงสถานะของแต่ละวิธีตามจริง

## เส้นทางแต่ละรายการ

| รายการ | ขั้นตอนที่เสนอใน G2 | ผลหรือทางกลับ |
| --- | --- | --- |
| รหัสผ่าน | กรอกรหัสผ่านปัจจุบัน รหัสผ่านใหม่ และยืนยันรหัสใหม่ การลืมรหัสผ่านใช้แบบกู้รหัสผ่านเดิม | เมื่อยืนยันว่าเปลี่ยนสำเร็จให้แจ้งผลและกลับหน้าแสดงรายการ วิธีจัดการเซสชันหลังเปลี่ยนรหัสยังรอสรุป |
| ยืนยันตัวตนก่อนแก้อีเมลหรือเบอร์ | ตัวอย่างใช้ OTP ทางอีเมลบัญชีเดิมสำหรับบัญชีที่มีสิทธิ์ใช้วิธีนี้ สมาชิกกดขอรหัสเอง กรอกรหัส 6 หลัก และกลับไปทำรายการที่เริ่มไว้หลังผ่านการยืนยัน | รหัสผิดแสดงในขั้นกรอก รหัสหมดอายุให้ขอใหม่ตามเงื่อนไขที่ใช้กับรายการนี้ วิธียืนยันอื่นและอายุสิทธิ์สำหรับทำรายการยังรอสรุป |
| เปลี่ยนอีเมล | ยืนยันตัวตน → กรอกอีเมลใหม่ → ยืนยันสิทธิ์เข้าถึงอีเมลใหม่ ตัวอย่างเสนอ OTP ทางอีเมลใหม่ | อีเมลเดิมยังเป็นอีเมลบัญชีจนยืนยันอีเมลใหม่และระบบยืนยันว่าเปลี่ยนสำเร็จ จึงแสดงค่าใหม่ เมื่อแก้อีเมลที่ขอ ให้ยืนยันปลายทางใหม่อีกครั้งตามข้อกำหนดที่จะตกลง |
| เพิ่มหรือเปลี่ยนเบอร์โทร | ยืนยันตัวตน → ตรวจค่าปัจจุบัน → กรอกเบอร์ใหม่พร้อมรหัสประเทศ → ไปขั้นถัดไป | G2-r1 ครอบคลุมถึงกรอกเบอร์ วิธีพิสูจน์ว่าเบอร์ใหม่เป็นของสมาชิกและการเปิดใช้เบอร์ใหม่รอสรุป เบอร์ปัจจุบันใช้ตามสถานะที่ยืนยันแล้ว |
| Google | แสดงสถานะเชื่อมบัญชีตามจริง | ใช้หน้าเดียวกับวิธีเข้าสู่ระบบอื่น |

กติกาเดิมให้ใช้อีเมลสำหรับ OTP และกู้รหัสผ่าน และให้ใช้เบอร์โทรคู่กับรหัสผ่านสำหรับเข้าใช้ แบบนี้ใช้องค์ประกอบ OTP 6 ช่องที่เคยตรวจรับเป็นตัวอย่าง การกำหนดวิธียืนยันแต่ละประเภท โควตา อายุรหัส เวลาส่งซ้ำ และกรณีเข้าถึงอีเมลเดิมไม่ได้ต้องสรุปสำหรับรายการแก้ข้อมูลโดยเฉพาะ [ข้อกำหนด Auth](../../dsd-001/home-auth-desktop-system-requirements.md) · [แบบ Auth ที่อนุมัติ](../../dsd-001/home-auth-g4-r1/README.md)

## สถานะที่ใช้ร่วมกัน

- **ฟอร์มพร้อมกรอกและผิดพลาด** ช่องกรอกชื่อและประเภทข้อมูลชัด ข้อผิดพลาดที่ระบุช่องได้อยู่ใต้ช่อง เมื่อกดส่งให้โฟกัสช่องแรกที่แก้ได้ รหัสผ่านแสดงเป็นจุดจนผู้ใช้เลือกเปิดดู ลิงก์กู้รหัสผ่านเปิดเส้นทางเดิม กติกาความยาวและรหัสผ่านที่อนุญาตให้ใช้กับการเปลี่ยนรอสรุป
- **กำลังส่งหรือกำลังตรวจ** แจ้งสถานะตามรายการและพักการกดซ้ำ สถานะขอรหัสใช้หลักเดียวกับ UI Auth ตามข้อกำหนดของรายการ
- **ส่งหรือเปลี่ยนไม่สำเร็จที่ยืนยันได้** แจ้งใกล้จุดดำเนินการ เก็บค่าอีเมลหรือเบอร์ที่เหมาะสมสำหรับแก้หรือลองใหม่ การตรวจว่าค่าใหม่ใช้ได้ใช้ถ้อยคำที่ให้ผู้ใช้แก้ได้โดยไม่เปิดเผยเจ้าของบัญชีอื่น
- **ผลยังไม่ยืนยัน** ตรวจผลเดิมก่อนแสดงว่าสำเร็จหรือให้ส่งใหม่ ค่าที่แสดงเป็นค่าของบัญชีที่ระบบยืนยันได้
- **รหัสผิด หมดอายุ หรือส่งใหม่** ใช้สถานะใกล้ช่องกรอก การตรวจอัตโนมัติเมื่อครบ 6 หลักและการส่งรหัสใหม่เป็นรูปแบบเสนอจาก Auth ใช้เท่าที่ได้รับอนุมัติสำหรับรายการนั้น
- **หมดเซสชันหรือยกเลิก** ใช้ทางกลับเข้าสู่ระบบและหน้าแสดงรายการที่ตรวจสิทธิ์แล้วตามบริบท ผลของคำขอที่ส่งไปยึดจากสถานะจริง การกลับมาทำรายการต่อและวิธีกู้เมื่อไม่มีสิทธิ์ที่จำเป็นยังรอสรุป รหัสผ่านและ OTP ใช้เฉพาะในขั้นกรอกนั้น
- **โฟกัสและการแจ้งผล** เริ่มที่หัวข้อหรือช่องแรกที่เกี่ยวข้อง แจ้งผลใกล้ฟอร์ม ย้ายโฟกัสกลับไปยังรายการหรือหัวข้อเมื่อปิดหรือจบขั้นตอน พฤติกรรมจริงของคีย์บอร์ดและโปรแกรมอ่านหน้าจอต้องทดสอบกับระบบ

## จุดตรวจรับของชุดนี้

1. เห็นทางเข้าจากโปรไฟล์และรายการจัดการที่ใช้ได้ตามชนิดบัญชี ทั้งเดสก์ท็อปและมือถือ
2. การยืนยันตัวตนและการยืนยันอีเมลใหม่เป็นคนละขั้นที่ระบุปลายทางชัด การแสดงค่าหลังเปลี่ยนเกิดหลังมีผลยืนยัน
3. แบบเพิ่มและเปลี่ยนเบอร์หยุดที่จุดส่งต่อก่อนขั้นพิสูจน์สิทธิ์ของเบอร์ใหม่ ผู้ตรวจเห็นว่าส่วนใดต้องพิจารณาต่อ
4. ภาพแสดงตัวอย่างสำเร็จ ผิดพลาด และหมดอายุ ส่วนสถานะระหว่างส่ง ผลยังไม่ทราบ และเซสชันหมดอายุมีข้อกำหนดอ้างอิงสำหรับออกแบบหรือทดสอบต่อ
