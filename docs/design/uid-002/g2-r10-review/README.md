## เงื่อนไขที่กำกับแบบ

- ก่อนข้อมูลชุดแรกมาถึง แสดงข้อความกำลังโหลด จำนวนผลปรากฏเมื่อมีผลตอบกลับที่ใช้ได้ Skeleton มีเฉพาะโครงรูปและข้อความ
- ระหว่างใช้ตัวกรอง ผลเดิมกับสรุปเงื่อนไขที่ใช้อยู่ยังเป็นชุดเดียวกัน ส่วนค่าในแผงเป็นค่าที่ส่งค้นหา ล็อกการส่งซ้ำและพักการแก้ตัวกรองช่วงรอคำขอนั้น ผู้ใช้ปิดแผง Mobile เพื่อกลับดูสถานะการค้นหาที่ส่งแล้วได้
- เมื่อใช้ตัวกรองล้มเหลว เก็บค่าที่ส่งไว้ให้ลองใหม่ เมื่อผู้ใช้แก้ค่าต่อ ให้คำสั่งหลักกลับเป็น **ใช้ตัวกรอง** และส่งค่าร่างชุดใหม่
- เมื่อโหลดหน้าถัดไปล้มเหลว เลขหน้าปัจจุบันยังตรงกับรายการที่แสดง คำสั่งลองใหม่ขอหน้าที่ต้องการด้วยตัวกรองเดิม
- คำขอที่ส่งทีหลังเป็นตัวกำหนดผลล่าสุด ผลตอบกลับของคำขอก่อนหน้าต้องผ่านการตรวจบริบทก่อนแสดง จำนวนผล สรุปเงื่อนไข เลขหน้า และรายการเปลี่ยนเป็นชุดเดียวกัน
- ทุกภาพจองความสูงไว้ตั้งแต่เริ่ม โหลดล้มเหลวเฉพาะภาพจะเก็บชื่อบ้าน ข้อมูล ราคา หัวใจ และตัวเลื่อนภาพไว้ตามตัวอย่าง [กติกาภาพ Q-07](../../uxd-002/review-decisions.md)
- สถานะโหลดประกาศให้เครื่องอ่านหน้าจอทราบผ่านข้อความสถานะ และบริเวณผลมีสถานะกำลังทำงาน Skeleton ซ่อนจากเครื่องอ่านหน้าจอ ปุ่มระหว่างรอป้องกันการกดซ้ำ ผลสำเร็จจากการเปลี่ยนหน้าย้ายโฟกัสไปหัวข้อผล ส่วนข้อผิดพลาดประกาศโดยเก็บโฟกัสไว้ให้ผู้ใช้ลองใหม่ได้
- ตัวบอกการโหลดในไวร์เฟรมเป็นภาพนิ่ง การเคลื่อนไหวใช้ค่าความต้องการลดการเคลื่อนไหวของผู้ใช้ ระยะเวลาที่เริ่มแสดงรอนานกับระยะหมดเวลารอจะผูกกับคำขอจริงในงานระบบ

ตรวจภาพและขอบเขตเลเยอร์ของทั้ง 18 หน้าจอ พร้อมตรวจว่าค่าค้นหาและเลขหน้าสอดคล้องกับผลเดิมในช่วงรอ รูปมีพื้นที่เท่าเดิมเมื่อเปลี่ยนเป็นสถานะโหลดหรือล้มเหลว การส่งคำขอ การลองใหม่ โฟกัส และเครื่องอ่านหน้าจอต้องตรวจในงาน implementation
