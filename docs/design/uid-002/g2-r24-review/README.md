## พฤติกรรม

เมื่อข้อมูลรายการได้แล้วแต่รูปยังมาไม่ครบ ให้พื้นที่รูปที่รอเป็น Skeleton ส่วนชื่อบ้าน ทำเล ความจุ ห้องนอน และราคาอ่านได้ ไม่แทนข้อความที่โหลดสำเร็จด้วย Skeleton อีกครั้ง ขนาดรูปและขนาดการ์ดเท่าเดิมเพื่อรักษาตำแหน่งรายการ

เมื่อรูปหนึ่งโหลดไม่ได้ ให้แสดงไอคอนกับ **โหลดรูปไม่ได้** เฉพาะภาพนั้น กรอบภาพไม่ยุบ ชื่อและราคายังอยู่ กดการ์ดเปิดรายละเอียดได้ และเมื่อบ้านมีหลายภาพยังเลื่อนไปภาพอื่นได้ตาม [กติกา Q-07](../../uxd-002/review-decisions.md) ไม่มีปุ่มลองใหม่เพิ่มเติม

ปุ่มบันทึกที่พักและตัวบอกตำแหน่งภาพคงตำแหน่งเดิม การเปิดรายละเอียดและการเลื่อนภาพต้องแยกการกระทำไม่ให้เลื่อนรูปแล้วเปิดรายละเอียดโดยไม่ตั้งใจ มีชื่อกำกับรูปตามบ้านและแจ้งสถานะให้เทคโนโลยีช่วยเหลือตามหน้าที่ ส่วน Skeleton เป็นการตกแต่ง ภาพนี้ยังเป็นไวร์เฟรมนิ่งจึงไม่ยืนยันเอฟเฟกต์เคลื่อนไหว

## ผลตรวจ

ใช้บ้านสวนพัทยาเป็นตัวอย่างเดียวกันทั้ง 4 เฟรม ชื่อ ความจุ ห้องนอน และราคาเท่ากัน Desktop การ์ด 340 × 291 รูป 340 × 207 Mobile การ์ด 358 × 305 รูป 358 × 221 ทั้งสองสถานะไม่เปลี่ยนขนาด ไม่มีปุ่มลองใหม่ในตัวอย่างการ์ด

ตรวจขอบเขตพบเฉพาะเนื้อหาหน้าตาม viewport 4 จุดกับพื้นที่เลื่อนตัวกรอง 2 จุด ตรวจภาพ Mobile ระหว่างโหลดกับโหลดไม่ได้แล้ว ข้อมูลบ้านยังอ่านได้ การเรียกรูป การเปลี่ยนภาพ การแตะ โฟกัส และเครื่องอ่านหน้าจอยังต้องตรวจใน runtime
