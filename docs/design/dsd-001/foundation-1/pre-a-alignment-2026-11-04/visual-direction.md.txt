## วิธีสร้างและข้อจำกัด

สร้างด้วย built-in ImageGen เป็น raster direction studies แยกสามแนว ไม่ใช้ร่างเก่าเป็นภาพอ้างอิง แต่ละภาพมือถือใช้ Desktop ของแนวทางนั้นเป็น reference เพื่อรักษาบุคลิก ภาพที่พักและข้อมูลในภาพเป็นตัวอย่างที่สร้างขึ้น ไม่ใช่ inventory ราคา availability หรือคำรับรองจริง

Prompt กำหนด Mitr และ palette ของ papaipak แต่ raster ไม่พิสูจน์ font family ที่ render หรือค่าสีของ semantic tokens แบบตรงตัว การยืนยันฟอนต์จริง ขนาด spacing/radii สี/contrast ทุก state และ responsive behavior ยังต้องทำใน foundation specifications และขั้นที่เกี่ยวข้อง ไม่มี supplementary font ได้รับอนุมัติจากภาพเหล่านี้

ภาพมีการใช้เส้นโค้ง ชั้นภาพ เงา และเส้นนำสายตาตาม feedback ของเจ้าของ กฎทั่วไปของ Taste Skill ที่ต่างจากคำขอและ project direction ไม่ใช้ลบลูกเล่นที่มีหน้าที่ต่อ composition; selected layouts และ approved UX ยังคงเป็นข้อจำกัด

ใช้ Awesome DESIGN.md / Airbnb snapshot เพื่อศึกษา photo-led marketplace และ information density เท่านั้น ไม่รับสี ฟอนต์ บริการ หรือ business rules ของ reference มาใช้ การสุ่ม reference จาก Taste Skill เคยให้ full-screen photo, split-stage และ dark-room ซึ่งขัดกับ discovery/white-base/layout constraints จึงไม่ใช้เป็นโครงหน้า

## OPEN-001 และหลักฐาน contrast

คำนวณ nominal solid-color pairs ด้วยสูตร sRGB relative luminance และเทียบ threshold โดยไม่ปัดเศษก่อนตัดสิน ตาม [W3C SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html):

| คู่สี | Ratio ประมาณ | Normal text AA |
|---|---:|---|
| White บน Pink | 2.705:1 | ไม่ผ่าน |
| Navy บน Pink | 5.078:1 | ผ่านเฉพาะคู่สี solid นี้ |
| Navy บน White | 13.738:1 | ผ่านเฉพาะคู่สี solid นี้ |

ภาพเสนอ Navy label บน Pink เป็น candidate treatment เดียวกันทั้งสามแนว A มีการแก้สีราคาและ badge จากภาพแรกก่อนส่งรุ่นปัจจุบัน ต่อมาเจ้าของเลือก **ชมพูเดิม #FD6E88 / ขาว #FFFFFF** เป็น CTA visual reference และไม่เลือกเฉดเข้มที่เสนอ ผลคำนวณไม่ได้รับรองทุก pixel/state หรือปิด OPEN-001 ดู [บันทึกปัจจุบันใน token sheet](token-sheet.md), [CTA selection](foundation-1/cta-selection.json) และ [ผลคำนวณเดิม](review-2/contrast-evidence.json)

## Acceptance และประเด็นค้าง

- มีสามแนวทางใหม่ พร้อม Desktop/Mobile และเหตุผล/trade-off ให้เปรียบเทียบ
- ภาพ Desktop แสดงหมวดเจ็ดรายการและการ์ดสี่คอลัมน์ Mobile แสดงแถบหมวดที่มีเนื้อหาต่อออกนอกจอและการ์ดหนึ่งคอลัมน์; ไม่ใช่ผลทดสอบ scroll หรือ responsive runtime
- OPEN-001, OPEN-002 และ OPEN-005 ยังเปิด ไม่รับรอง source provenance หรือ final visual baseline
- ภาพ B Mobile ยังมีลิงก์ “ดูทั้งหมด” สีชมพู และภาพ C มี favorite icon สีชมพู ต้องกำหนดคู่สี/non-text contrast ใหม่ใน specification ก่อนตรวจรับส่วนควบคุมเหล่านี้
- ไม่ได้ทดสอบ Tablet, 320px, zoom/reflow, keyboard, screen reader, motion, carousel, sticky หรือ business flows จริง
- Direction ปัจจุบันคือ `A / review-2` ตาม owner change; การเลือก B ก่อนหน้าเก็บเป็นประวัติ แบบ native `pencil-A-1` และ final foundation approval ยังรอแยก
- Final foundation approval, full component states, page designs และ frontend ยังคงมี gate ของตนเอง
