# Home Auth · OTPหลัก รหัสผ่านเป็นทางเลือก

5 พฤศจิกายน2026 · DSD-001/C2 · **เลือกEmail OTPแล้ว; PhoneยังPassword รอข้อสรุปSignupก่อนโครงใหม่**

อ้าง [คำแก้ไขเจ้าของ](home-auth-otp-primary-amendment.json): ขั้นปกติใช้OTP ผู้ใช้ที่เลือกLoginด้วยรหัสผ่านเองจึงเข้าสู่ฟอร์มรหัสผ่าน Googleยังเป็นทางเลือกเดิม

## ผลต่อแบบปัจจุบัน

- ร่างLogin-r4ที่นำไปรหัสผ่านอัตโนมัติไม่ใช่defaultล่าสุด และไม่ได้รับอนุมัติภาพจากคำชี้แจงนี้ เก็บlayer/PNGเดิมไว้เป็นประวัติและใช้พิจารณาสาขารหัสผ่าน ไม่ลบหลักฐาน
- OTPต้องมีstateรับรหัส/กรอก/ผิดหรือหมดอายุ/ส่งซ้ำ/รอผลและสลับไปใช้รหัสผ่าน แต่ยังไม่สร้างหน้าจอหรือกำหนดจำนวนหลัก อายุรหัส เวลารอ จำนวนครั้งเอง
- รหัสผ่านขั้นต่ำ8และconfirmationสำหรับตั้งรหัสที่เคยเลือกยังมีผลเมื่อใช้สาขารหัสผ่าน แต่required passwordของSignupเดิมต้องหารือให้ตรงกับการสมัครผ่านOTP ไม่บังคับรหัสผ่านในOTPโดยเงียบหรือถือว่าลบRegisterที่รับแล้วอัตโนมัติ
- Forgotผ่านemail linkเดิมคงเป็นฐานสาขารหัสผ่าน ไม่เปลี่ยนเป็นกู้รหัสด้วยOTPเอง
- OTPทางโทรศัพท์ไม่เท่ากับยืนยันอีเมล ไม่เปลี่ยนข้อเลือกยืนยันอีเมลแบบข้ามได้ หรือGoogleเติมprofileภายหลังเอง

## คำถามถัดไปหนึ่งข้อ

ให้OTPครอบคลุมช่องทางใดก่อน:

1. ตามข้อมูลที่กรอก: อีเมลรับทางอีเมล, เบอร์รับทางSMS
2. OTPเฉพาะอีเมลก่อน; เบอร์ยังใช้รหัสผ่าน
3. OTPเฉพาะเบอร์ก่อน; อีเมลยังใช้รหัสผ่าน

นี่คือขอบเขตออกแบบหน้าจอ ไม่ใช่การตั้งค่าprovider/SMS/ส่งอีเมลจริง เมื่อเลือกช่องทางแล้วจึงปรับG2และเสนอเรื่องSignup/การตั้งรหัสที่ยังค้างทีละข้อก่อนรับแบบรวม ไม่เริ่มUID-005/Backend/Frontend/Mobileหรือเชื่อมproviderจากคำเลือกUI

## ผลเลือกช่องทาง

เจ้าของเลือก2ให้OTPเฉพาะอีเมลก่อนตาม [หลักฐาน](home-auth-email-otp-scope-decision.json) เบอร์โทรยังpassword อีเมลมีpasswordเมื่อเลือกเองและGoogleคงเดิม ไม่มีSMS/phoneOTP ต้องหารือต่อว่าการสมัครด้วยอีเมลใช้OTPโดยไม่ตั้งpassword, เลือกวิธีสมัคร หรือคงpasswordบังคับเดิม ไม่ลบหรือบังคับpasswordโดยอนุมานจากคำเลือกช่องทางLogin
