## OTP input: ข้อสรุปที่รับแล้ว

- แยก6ช่อง เลื่อนช่องอัตโนมัติ ตรวจทันทีเมื่อครบ6 ไม่มีปุ่มยืนยันเพิ่ม
- รหัสผิดล้างและกลับช่องแรก; หมดอายุแยกขอใหม่; ตรวจระบบไม่ได้คงเลขและให้ลองเองตามstateที่รับ ไม่ตัดสินว่ารหัสผิด
- นับรอในปุ่มส่งอีกครั้งอย่างเดียว ครบเวลาไม่ส่งเอง `00:45`เป็นfixture ไม่ใช่ระยะเวลาที่เลือก
- วางเลข6หลักจากช่องใดก็แทนทั้งชุดและรักษาเลข0นำหน้า; ข้อความวางที่มีรหัสเดียวชัดเจนใช้รหัสนั้น วางใช้ไม่ได้ไม่ใส่และคงเลขเดิม ไม่เพิ่มwarning/selector/focus workflow
- Backspaceช่องว่างถอยและลบตัวก่อนหน้า; ช่องที่มีเลขลบช่องนั้นแล้วถอย แต่เลขพิมพ์ถัดไปเติมช่องที่เพิ่งลบ

อ้าง [input discussionและdecision links](home-auth-otp-input-discussion.md), [auto verification](home-auth-otp-auto-verification-decision.json), [quiet paste](home-auth-otp-quiet-paste-clarification.json) และหลักฐานr6–r16ตามspecหลัก ไม่ใช้เอกสารนี้แก้พฤติกรรมเหล่านั้น

## ข้อเสนอสำหรับรับพร้อม G2 รวม

ข้อด้านล่างเป็นข้อเสนอที่เตรียมไว้ ไม่ใช่คำตอบใหม่ของเจ้าของ

| เรื่อง | ข้อเสนอและสิ่งที่ต้องตรวจจริงภายหลัง |
|---|---|
| Focus scope | มีAuth modalที่ใช้งานหนึ่งชุด ย้ายfocusเข้าช่องแรกที่ใช้ได้; OTPเข้าช่องแรกตามstate ปิดbackgroundจากการกด/Tabระหว่างเปิด modal |
| Tab/Shift+Tab | วนภายในmodalตามลำดับภาพ ข้ามcontrolที่inactive เปิดcountry pickerให้focusอยู่ในpickerตามหน้าที่แล้วคืนtriggerเมื่อปิด ไม่สร้างfocusableสำเนาช่องเลข |
| Escape | ปิดcountry popoverก่อนเมื่อเปิดอยู่ กดEscapeเมื่อเหลือAuthmodalจึงปิดAuthตามclear-all/origin contract; ปุ่มXใช้ผลเดียวกัน |
| Pointerนอกpicker | กดภายในAuthแต่นอกcountry pickerปิดเฉพาะpicker กดพื้นที่มืดนอกAuthปิดAuthตามคำตัดสินเดิม |
| Enter | ในformเรียกprimaryตามขั้นเมื่อพร้อม; ในcountry searchเลือกตัวเลือกที่highlightedโดยไม่ส่งRegister; OTPครบ6ใช้auto-checkเดิม ไม่สร้างsubmitซ้ำ |
| Back/สลับวิธี | ภายในAuthที่ยังเปิดรักษาข้อมูลที่เกี่ยวข้องตามflowที่รับ ไม่ล้างHome เมื่อdismissใช้clear-allเดิม Googlecancelรักษาidentifierและไม่ขอOTPเอง |
| Return focus | เมื่อปิดกลับtriggerเดิมถ้ายังอยู่ เช่นHeader Loginหรือหัวใจ ถ้าtriggerหายให้จุดควบคุมที่เกี่ยวข้องใกล้ที่สุดที่ยังใช้ได้ การสำเร็จ/เปลี่ยนหน้ารับfocusตามปลายทาง ไม่ดึงกลับHomeซ้ำ |
| Pending | พักการส่งซ้ำ/ช่องที่เปลี่ยนผลคำขอและmethod switchingตามภาพaccepted Closeใช้ได้ การretryต้องเหมาะกับผลคำขอจริง ไม่ถือnetwork errorว่าปลอดภัยให้ส่งซ้ำเสมอ |
| Show/hide password | สลับการมองเห็นอย่างเดียว ไม่ล้างค่า; labelและaccessible nameบอกผลปัจจุบัน ไม่เพิ่มpolicyการพิมพ์/วางหรือmaximumเอง |
| Feedback | ผูกerrorกับinput, อ่านstatus/error/successให้assistive technologyโดยไม่ประกาศซ้ำทุกkeypress Form-level errorไม่ทำช่องที่ไม่ทราบสาเหตุเป็นinvalid |
| Viewport/scroll | Modalยาวเลื่อนอ่านและเข้าถึงปุ่มสุดท้าย/ปิดได้ในDesktopที่สูงน้อยกว่าfixture โดยไม่ให้Homeด้านหลังเลื่อนแทน ต้องตรวจfocusไม่หลุดหรือถูกบังในต้นแบบจริง |
| Heroระหว่างAuth | พักHeroอัตโนมัติขณะAuthเปิด เมื่อปิดและไม่มีเหตุพักอื่นเสนอเริ่มนับ7วินาทีใหม่หลังภาพพร้อม; ถ้าผู้ใช้กดพักเองยังพักต่อ ไม่ยกเลิกเหตุพักอื่นหรือเปลี่ยนภาพทันที |
| Reduced motion | รักษาข้อมูล/การเลือก/สถานะทั้งหมด ลดการเคลื่อนไหวตกแต่งและแสดงbusyอย่างอ่านรู้เรื่อง ไม่กำหนดระยะเวลาanimationใหม่จากภาพนิ่ง; รูปแบบfocusจริงรอG3 |

Heroพื้นฐานที่รับแล้วคือค้าง7วินาที เลื่อน800msด้วย`cubic-bezier(.4,0,.2,1)` และเริ่มนับใหม่หลังเลื่อนเอง/ออกจากhover/ปิดSearch โดยmanual pauseมีผลต่อ อ้าง [Hero spec](hero-banner-carousel-spec.md) การเพิ่มAuth pause/resumeข้างบนเป็นข้อเสนอในขอบเขตG0นี้ ไม่แก้policybackground tab/keyboardของHeroทั้งระบบโดยอัตโนมัติ

## สถานะและขอบเขตการตรวจ

รอผูกcurrent frame/state inventoryและversionที่เสนอรับG2รวม พร้อมให้เจ้าของตรวจข้อเสนอด้านบน ไม่มีการทดสอบTab/Escape/IME/screen reader/scroll/motionจริงในภาพPencil จึงยังไม่ลงผลpassด้านaccessibility/runtime

ประเทศที่รองรับจริง/normalization/credential matching/provider/session/OTP expiry/cooldown/quotaและdeliveryคงแยกเป็นงานสัญญาระบบ ข้อเสนอkeyboardไม่เลือกค่าเหล่านี้ Favorite toastตำแหน่งเต็มหน้า/ระยะเวลาและG3 visualยังต้องตรวจ ไม่ใช้r28cropped sampleรับแทน

G2รวมยังไม่รับ High-Fiยังไม่เริ่ม OPEN-001ยังเปิด Mobileพัก ไม่มีFrontend/backend/SDK/deploy/commit/pushหรือTaskใหม่
