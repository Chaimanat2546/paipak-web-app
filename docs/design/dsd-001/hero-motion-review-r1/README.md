# Hero motion review-r1 · ความเร็วเปลี่ยนภาพ

สถานะล่าสุด: เจ้าของรับ [Home Desktop-r16พร้อมข้อค้างเดิม](../home-desktop-r16-final-review/owner-home-acceptance.json) และปิดรอบออกแบบDesktopแล้ว ค่า800msและกติกาเริ่ม7วินาทีใหม่คงตามหลักฐานรายข้อด้านล่าง ตัวอย่างเดิมยังเป็นmanual motion sample ไม่ได้กลายเป็นruntime testจากการรับแพ็กเกจ

อัปเดตเล่นต่อ: เจ้าของเลือก1ให้เริ่มนับ7วินาทีใหม่หลังเลื่อนเอง/เอาเมาส์ออก/ปิดค้นหา การกดพักเองยังรอปุ่มเล่น และเหตุพักที่ยังค้างอยู่มีลำดับเหนือการเริ่มนับ ดู [หลักฐาน](owner-restart-policy-decision.json) ตัวอย่างmotionเดิมยังเป็นmanual sample ไม่ได้เพิ่มautoplaytimerจากการบันทึกนโยบายนี้

5 พฤศจิกายน2026 (Asia/Bangkok) · เจ้าของเลือกตัวอย่าง800msแล้ว

เจ้าของตอบ “3” เลือกนุ่มช้า800msตามตัวอย่าง รวมeasingที่ใช้ในตัวอย่าง `cubic-bezier(.4,0,.2,1)` ดู [หลักฐานเลือกmotion](owner-motion-acceptance.json) เวลาค้างยัง7วินาที การเลือกไม่ทดสอบautoplaytimerหรือรับนโยบายเริ่มนับใหม่/เล่นต่อ

เจ้าของรับหน้าตาcontrols defaultหลายสไลด์แล้วด้วยตัวเลือก1 ดู [หลักฐาน](../hero-banner-carousel-r3/owner-multislide-controls-acceptance.json) ขั้นนี้เปรียบเทียบเฉพาะระยะเวลาเลื่อนภาพแนวนอน ไม่เปลี่ยนเวลาค้าง7วินาทีต่อภาพที่ยืนยันแล้ว

| ตัวเลือก | ระยะเวลาเลื่อน | ความตั้งใจ |
| --- | --- | --- |
| กระชับ | 400ms | เปลี่ยนไว |
| สมดุล | 600ms | ข้อเสนอแนะนำ เห็นการเลื่อนโดยไม่ค้างนาน |
| นุ่มช้า | 800ms | ช่วงเคลื่อนยาวขึ้น |

ทั้งสามใช้easingเดียวกัน `cubic-bezier(.4,0,.2,1)` เพื่อเทียบduration โดยคงภาพสำเร็จรูปที่เลื่อนและชั้นSearch/ขอบขาว/controlsที่อยู่คงที่ เจ้าของเลือก800msแล้ว;400/600msเก็บเป็นทางเลือกที่ไม่ได้เลือก
