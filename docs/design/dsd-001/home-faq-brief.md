# Home Desktop · FAQ supplement brief

5 พฤศจิกายน2026 (Asia/Bangkok) · DSD-001 bounded Home supplement · G0 approved

เจ้าของตอบ1ให้เริ่มPencilตามแผนแล้ว ดู [หลักฐานG0](home-faq-g0-approval.json) การอนุญาตให้สร้างแบบไม่ใช่การรับหน้าตาFAQหรือเวอร์ชันHomeใหม่

## ข้อกำหนดที่เจ้าของยืนยัน

- เจ้าของขอเพิ่มคำถามที่พบบ่อยในHome หลังรับHome Desktop-r16แล้ว
- คำถาม/คำตอบมาจากหลังบ้านที่ผู้ดูแลเขียน ไม่ล็อกคำถามจริงไว้ในหน้าเว็บ ยังไม่ออกแบบหรือสร้างระบบหลังบ้านจากคำขอนี้
- เจ้าของตอบ1ให้เปิดคำตอบทีละข้อ เปิดข้อใหม่แล้วปิดข้อเดิม ไม่ใช่multi-openหรือแสดงคำตอบทั้งหมดพร้อมกัน

## แผนที่เสนอเพื่อรับG0

เพิ่มหนึ่งsectionต่อจากบทความและก่อนFooterในHome Desktop รักษาA/papaipak/Mitr/สีแบรนด์และส่วนที่รับแล้ว ใช้ข้อมูลจำลองสำหรับตรวจความยาวและการจัดวาง ไม่สร้างหรือยืนยันนโยบายการชำระเงิน/ยกเลิก/เข้าพักที่ยังไม่ตกลง

เสนอdefaultปิดทุกข้อก่อนเปิดอ่าน และแสดงรายการที่พร้อมตามลำดับที่หลังบ้านจัดให้ ไม่ตั้งจำนวนสูงสุดหรือเพิ่มหน้ารวมFAQ/ปุ่มดูทั้งหมดเอง หากไม่มีรายการพร้อมเสนอซ่อนทั้งsectionพร้อมช่องว่าง เนื้อหาว่างไม่สร้างคำตอบสมมติแทน ส่วนกติกาข้อมูล/โหลดจริงยังไม่ถือว่ารับจากbriefนี้

หลังเจ้าของรับG0 จัดทำPencil review copyและsection states: default closed, one expanded, long question/answer, no-ready-items context พร้อมภาพตรวจและspecเสริม จากนั้นขอรับแบบและเวอร์ชันใหม่แยก ไม่แก้Home-r16ที่รับไว้หรือขยายapprovalเดิมไปครอบคลุมFAQ

## ขอบเขตและหลักฐาน

- ฐาน: [Home Desktop-r16ที่รับแล้ว](home-desktop-r16-final-review/owner-home-acceptance.json)
- งาน: ออกแบบการแสดงFAQเฉพาะDesktop พร้อมข้อมูลจำลองและstate specification
- ไม่ทำ: application code/CSS, backend/CMS/API, deployment, Mobile, Taskอื่น หรือการสร้างนโยบายธุรกิจจริง
- Gate: [AGENTS.md](../../../AGENTS.md) และ [governance workflow](../governance/05-design-workflow.md) ให้รับแผนก่อนUI Design การตอบ1เรื่องเปิดทีละข้อไม่ใช่การรับแผนหรือหน้าตาทั้งชุด

## เกณฑ์ตรวจที่เสนอ

1. FAQอยู่ก่อนFooterและเข้ากับHomeที่รับไว้ ไม่แก้ส่วนอื่นเพื่อเพิ่มsectionนี้
2. แบบระบุการเปิดได้สูงสุดหนึ่งข้อ และdefaultที่เจ้าของรับ; คำถามยาวไม่ชนไอคอน คำตอบยาวไม่ถูกตัดเพื่อบังคับความสูง
3. เนื้อหาเป็นข้อมูลที่แยกจากvisual ไม่กำหนดคำถามจริงแทนหลังบ้าน ไม่มีระบบแก้ไขเนื้อหาหรือbackendจริงในรอบนี้
4. มีตัวอย่างclosed/open/long/emptyตามขอบเขตที่รับ และบันทึกข้อค้างkeyboard/motion/dataโดยไม่อ้างว่าทดสอบจากภาพนิ่ง
5. เจ้าของรับแบบFAQ/เวอร์ชันรวมใหม่แยกก่อนเกี่ยวข้องกับFrontend Home-r16และข้อค้างเดิมยังเก็บตามหลักฐาน

สถานะ: เจ้าของรับแผน ตำแหน่ง/default/emptyและอนุญาตเริ่มวาดในPencilแล้ว แบบFAQและเวอร์ชันรวมยังต้องรับแยก
