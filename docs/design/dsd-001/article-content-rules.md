# Article content rules · Home

4 พฤศจิกายน 2026 · ตรวจทีละเงื่อนไข

เจ้าของเลือก1ต่อคำถามถ้าบทความไม่มีรูปปก จึงกำหนดว่า **ไม่แสดงบทความเรื่องนั้นบนHome** ไม่ใช้ปกกลางหรือข้อความล้วนแทนจากคำตอบนี้

ขอบเขตเป็น eligibility ของส่วนบทความบน Home ไม่ลบเนื้อหาบทความหรือเปลี่ยนการแสดงในหน้ารวม/หน้าอ่าน กรณีรูปมี URL แต่โหลดล้มเหลวชั่วคราวยืนยันแยกใน Q4 ด้านล่าง

เจ้าของเลือก 1 ต่อคำถามกรณีเรื่องเด่นไม่มีปก จึงให้เลื่อนเรื่องถัดไปที่พร้อมขึ้นเป็นเรื่องเด่นและคงลำดับที่คัดไว้ เรื่องที่เลื่อนแล้วไม่แสดงซ้ำในตำแหน่งรอง ดู [ตัวอย่าง Pencil](article-availability-r1/README.md) การเติมเรื่องเมื่อจำนวนชุดคัดเหลือไม่ครบยืนยันแยกภายหลังใน Q7 ด้านล่าง

เมื่อชุดที่คัดไว้ไม่เหลือเรื่องที่แสดงได้ เจ้าของตอบ “ใช้บทความล่าสุดไง” จึงใช้บทความล่าสุดที่พร้อมแสดงและมีรูปปกมาแทน โดยเรียงใหม่ไปเก่า เรื่องแรกเป็นเรื่องเด่นและเรื่องถัดไปเป็นเรื่องรองตามlayoutเดิม ไม่ใช้ปกกลางหรือชุดสำรองที่ต้องคัดเองเพิ่ม

คำตอบกรณีชุดคัดว่างไม่เปลี่ยนการคัดเองเป็น latest ทุกครั้ง ส่วนกรณีชุดคัดยังมี 1–2 เรื่อง เจ้าของเลือก `2` ใน closeout Q7 ให้เติมบทความล่าสุดที่พร้อมขึ้นแสดงจนได้ 3 เรื่อง โดยคงเรื่องที่คัดไว้ก่อนตามลำดับเดิม แล้วเติมเรื่องอื่นตามวันที่แก้ไขล่าสุดจากใหม่ไปเก่า ไม่ซ้ำกับเรื่องที่แสดงแล้ว เรื่องแรกเป็นเรื่องเด่น อีกสองเรื่องเป็นเรื่องรอง ถ้าเรื่องพร้อมทั้งหมดมีไม่ถึง 3 ให้ใช้จำนวนจริงและผัง 1/2 เรื่องที่รับไว้ ไม่ใช้ช่องว่างหรือปกสำรองเพื่อให้ครบ ดู [หลักฐาน Q7](article-top-up-decision.json)

เจ้าของเลือก `2` ใน closeout Q6 ให้ “บทความล่าสุด” เรียงตามวันที่แก้ไขล่าสุดจากใหม่ไปเก่า เรื่องเก่าที่อัปเดตจึงกลับขึ้นก่อน ใช้กับเรื่องที่พร้อมแสดงตามกติกาเดิมและ latest fallback ไม่เปลี่ยนลำดับชุดคัดเอง ข้อนี้แทนข้อเสนอวันที่เผยแพร่ที่ยังไม่เคยรับ การผูก field จริง รวมถึงวันที่ขาดหรือเท่ากันยังต้องตรวจ data contract ไม่ถือว่ามี query ที่ทำงานแล้ว ดู [หลักฐาน Q6](article-latest-order-decision.json)

เจ้าของเลือก `1` ใน closeout Q2 ให้ซ่อนส่วนบทความทั้งหมดเมื่อทั้งคลังไม่มีเรื่องพร้อม แม้ใช้ latest fallback แล้ว ไม่แสดงหัวข้อ ข้อความว่าง หรือส่วนชวนค้นหาที่พักแทน และไม่ทิ้งพื้นที่ section ว่าง ดู [หลักฐาน](article-count-r1/owner-zero-story-decision.json) ไม่สร้าง Backend หรือกล่าวว่ามี query ที่ทำงานแล้ว

เจ้าของเลือก `1` ใน closeout Q3 กำหนดให้เรื่องที่แสดงบน Home ต้องมีรูปปก ชื่อ และลิงก์อ่านครบ หากขาดให้ข้ามเรื่องและใช้กติกาเลื่อนเรื่อง/fallback เดิม คำโปรยเป็นข้อมูลเสริม ต่อมาเมื่อตรวจภาพไม่มีคำโปรยใน R1 เจ้าของระบุ “ให้ใช้เนื้อหาแทน” จึงใช้ข้อความช่วงต้นของเนื้อหาบทความเมื่อไม่มีคำโปรย ทั้งเรื่องเด่นและเรื่องรอง สูงสุด 2 บรรทัดแล้ว ellipsis โดยรักษาเนื้อหาเต็ม ไม่เขียนสรุปใหม่ กติกานี้แทนการยุบพื้นที่คำโปรยที่เคยเลือกใน Q3 เท่านั้น ไม่เปลี่ยน required fields ดู [หลักฐานล่าสุด](article-body-fallback-r2/owner-instruction.json), [ประวัติ Q3](article-required-fields-decision.json) และ [ข้อกำหนดคำโปรย](article-excerpt-spec.md)

เจ้าของเลือก `1` ใน closeout Q4 กรณีข้อมูลมีปกแต่โหลดภาพล้มเหลว ให้ข้ามเรื่องนั้นในการแสดง Home ครั้งนี้และเลื่อนเรื่องพร้อมถัดไปขึ้นตามลำดับเดิมโดยไม่ซ้ำ ไม่ใช้ปกสำรองหรือปุ่มลองใหม่เฉพาะรูป ใช้กติกา fallback/ไม่มีเรื่องพร้อมเดิมตามเงื่อนไข ไม่ลบหรือยกเลิกเผยแพร่บทความ และไม่บันทึกความล้มเหลวชั่วคราวเป็นข้อมูลว่าบทความไม่มีปก สถานะกำลังโหลดอย่างเดียวยังไม่ถือว่าล้มเหลว ดู [หลักฐาน Q4](article-cover-failure-decision.json)

กติกา loading ปัจจุบัน: ข้อมูลพร้อมแสดงได้ทันที ระหว่างรอใช้ Skeleton เฉพาะส่วนตามภาพที่เจ้าของรับ หลังตรวจสาเหตุของการโหลดล้มเหลว เจ้าของเปลี่ยน Q5 เฉพาะการแสดง error: ให้ซ่อน section ทั้งหมดเมื่อโหลดรายการไม่ได้ตามกรณีนี้ ไม่แสดงข้อความผิดพลาด ปุ่มลองใหม่ หรือคำชวนให้รีเฟรช ส่วนอื่นยังใช้ต่อได้ ให้เก็บ log ภายในเพื่อทีมตรวจแก้ภายหลัง ไม่บันทึก successful empty result เป็น error และไม่ตีความ request failure ว่าเป็นคลังว่าง แม้ทั้งสองกรณีแสดงผลด้วยการซ่อนเหมือนกัน ดู [ข้อสรุปล่าสุด](article-hidden-r2/owner-decision.json) และ [กติกา loading](article-loading-decision.json) การเก็บ log ยังเป็นข้อกำหนด ไม่ได้เชื่อมระบบจริง

ดู [หลักฐานกติกา](article-content-rules.json) ภาพ [ใช้เนื้อหาแทนคำโปรย](article-body-fallback-r2/README.md), รูปเสีย/loading/error ยังตรวจต่อในชุดบทความรวม กติกานี้ยังไม่ใช่การทดสอบ runtime ไม่แก้ application code หรือเริ่ม Frontend Mobile พักและ OPEN-001 เปิด

คำชี้แจงล่าสุดของเจ้าของ: ออกแบบ Home เผื่อไว้ก่อน เพราะยังไม่ได้ออกแบบฟีเจอร์บทความ ใช้ body fixture ใน r2 ตรวจหน้าตาได้โดยไม่ต้องหาแหล่งบทความจริงตอนนี้ เมื่อทำฟีเจอร์ภายหลัง ข้อความที่แสดงต้องคัดจากเนื้อหาของบทความเรื่องนั้นและยังจำกัดสองบรรทัด ไม่แต่งคำอธิบายแยกแทนเนื้อหา ไม่แก้เนื้อหาฉบับเต็ม การยืนยันขั้นงานไม่ใช่การรับ appearance ดู [คำชี้แจง](article-stage-clarification.json)

## ข้อเสนอจำนวนรายการหลังคำถามเจ้าของ

เจ้าของถามกรณีมีเพียง 1–2 เรื่อง จึงมี [Article-count-r1](article-count-r1/README.md) จากนั้นรับภาพเรื่องเด่น 1 + เรื่องรอง 1 ตาม [หลักฐานกรณีสองเรื่อง](article-count-r1/owner-two-story-acceptance.json) ต่อมาเลือก `1` ใน closeout Q1 รับเรื่องเด่นขนาดเดิมจัดกึ่งกลางเมื่อมีเรื่องเดียว ตาม [หลักฐานกรณีหนึ่งเรื่อง](article-count-r1/owner-one-story-acceptance.json) และ Q2 ยืนยันการซ่อน section เมื่อทั้งคลังไม่มีเรื่องพร้อม ไม่แทนกติกา latest เมื่อชุดคัดว่างแต่คลังยังมีเรื่องพร้อม และไม่รับ article/Home version ทั้งชุดจากคำตอบเหล่านี้
