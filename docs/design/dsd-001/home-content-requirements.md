# Home: TikTok และบทความ / บันทึกความต้องการ

วันที่ 4 พฤศจิกายน 2026 (Asia/Bangkok) · หารือเพิ่มเติมใน DSD-001

สถานะ: บันทึกคำตอบเรื่องเนื้อหาและพฤติกรรมเบื้องต้น ยังไม่ใช่การอนุมัติขอบเขต UI เพิ่ม การตรวจรับ foundation หรือการเริ่ม UID-001

เจ้าของเลือก1ยืนยันสรุปความต้องการรวมในบทสนทนา แล้วให้ตรวจผลต่อ foundation ต่อ ผลอยู่ใน [บันทึกผลกระทบ](home-content-foundation-impact.md) โดยยังไม่อนุมัติ UI เพิ่มหรือ foundation ทั้งชุด

ภายหลังเจ้าของขอ “ออกแบบ ui เลยได้ไหม” จึงทำ [Home-media-ui-r1](home-media-ui-r1/README.md) บนสำเนา Home-r8 เพื่อเริ่มตรวจภาพจริงตามคำขอล่าสุด การอนุญาตให้ทำร่างแยกจากการตรวจรับแบบและ foundation ขั้นสุดท้าย

## ความต้องการที่ยืนยันในบทสนทนา

| เรื่อง | ข้อสรุป | หลักฐานคำตอบ |
| --- | --- | --- |
| TikTok: เนื้อหา | คัดคลิปหลายแนวมารวมกัน โดยส่วนใหญ่พาชมพูลวิลล่า | “2 มันจะเป็นคลิปที่เลือกมารวมๆ แต่ส่วนใหญ่ก็คือ พาชมพูลวิลล่า” ใช้คำอธิบายนี้เป็นหลัก ไม่ตีความเลข2ว่าเป็นคลิปเที่ยวอย่างเดียว |
| TikTok: จุดเล่น | เล่นตรงส่วนคลิปบน Home | เลือก3ต่อคำถามว่าจะเล่นในหน้า เปิดหน้าต่างทับ หรือไป TikTok |
| TikTok: แหล่งเนื้อหา | คัดลิงก์เองจากหลายช่อง | เลือก1ต่อคำถามเรื่องแหล่งคลิป |
| TikTok: เริ่มเล่น | ภาพปกนิ่งก่อน กดเล่นเอง และเล่นทีละคลิป | เลือก1ต่อคำถามเรื่องจังหวะเริ่มเล่น |
| บทความ: เนื้อหา | เขียนกันเอง มีหลายประเภท ไม่จำกัดว่าต้องเป็นคู่มือหรือที่เที่ยว | “อันนี้เขาเขียนกันเองมีทุกแบบ” ยังไม่ได้ระบุรายชื่อผู้เขียนหรือระบบจัดการเนื้อหา |
| บทความ: การเลือกขึ้น Home | คัดเลือกเอง คุมเรื่องและลำดับได้ | เลือก1ต่อคำถามเรื่องการแสดงบทความบน Home |

“เล่นทีละคลิป” เป็นพฤติกรรมที่ต้องออกแบบและทดสอบต่อ ไม่ใช่ผลทดสอบ player จริงบน papaipak การคัดลิงก์เองไม่อนุมัติ CMS, Admin, API integration หรือระบบดึงโพสต์อัตโนมัติ

## ผลต่อ foundation ที่ประเมินเบื้องต้น

- ใช้ A / Holiday Panorama, palette และ Mitr เดิม ไม่เปิดเลือกทิศทางหรือฟอนต์ใหม่
- ต้องตรวจบทบาทตัวอักษรของหัวข้อส่วน ชื่อบทความ คำโปรย และข้อมูลผู้สร้างคลิป กับ typography ที่มีอยู่ก่อนเสนอ role เพิ่ม
- ต้องแยกสัดส่วนภาพปกวิดีโอ/บทความออกจากรูปการ์ดบ้าน ไม่บังคับให้ข้อมูลทุกชนิดใช้ geometry ของ property card
- ต้องตรวจ controls, focus, loading/unavailable states และการเล่นทีละคลิปในขอบเขตใหม่ ไม่ถือว่าการรับ states ของการ์ดบ้านครอบคลุมเนื้อหาสองส่วนนี้แล้ว
- ตำแหน่ง section จำนวนที่เห็น รูปแบบแถว/กริด สัดส่วนปก และข้อความบนการ์ดยังไม่ได้เลือก ไม่เพิ่มตัวเลขเข้า token-sheet จากการบันทึกนี้
- Foundation-2-desktop ยังรอตรวจรับ Mobile ยังพัก และ OPEN-001 ยังเปิดตามเดิม

ผลข้างต้นเป็นรายการที่จะตรวจ ไม่ใช่การยืนยันว่า foundation ครบหรือจำเป็นต้องแก้ทุกหัวข้อ

## หลักฐานภายนอกที่อ่านแล้ว

1. [TikTok Embed Player](https://developers.tiktok.com/docs/en/embed-player): รองรับ player ใน iframe, การเริ่มเล่นโดยผู้ใช้ และคำสั่ง play/pause มีเหตุการณ์แจ้งข้อผิดพลาด การรองรับในเอกสารไม่แทนการทดสอบ browser หรือยืนยันทุกคลิปที่เลือก
2. [TikTok Embed Videos](https://developers.tiktok.com/docs/en/embed-videos): เอกสารระบุให้ย้ายไป Embed Player และคลิปที่ถูกลบจะไม่สามารถดูผ่าน embed ได้ด้วย จึงต้องมีข้อตกลง unavailable/fallback ภายหลัง
3. [POOLA Journal](https://www.poolapoolvilla.com/blog): อ่านโครงสร้างบทความที่มีรูป หมวด หัวเรื่อง คำโปรย และลิงก์หน้าอ่าน ใช้เป็นหลักฐานรายการข้อมูลเท่านั้น ยังไม่ได้ตรวจ screenshot เพื่อรับรอง visual quality หรือเลือกเป็นต้นแบบ

การค้นตัวอย่างเว็บโรงแรมรอบนี้ยังไม่ได้หน้า Home ที่ตรวจยืนยันว่ามีแถว TikTok ตรงกับความต้องการ ไม่อ้างว่าได้ต้นแบบภาพครบแล้ว ไม่ดึงรูป เนื้อหา ราคา รีวิว หรืออัตลักษณ์ของแหล่งอ้างอิงมาเป็น production assets

## รายการที่ต้องสรุปต่อ

- ยืนยันความเข้าใจรวมของบันทึกนี้ แล้วเสนอแนวทางพร้อม trade-offs ก่อนเลือกการจัดวาง
- ตรวจตัวอย่างที่เห็นภาพจริงก่อนเสนอแบบ เปรียบเทียบเฉพาะสิ่งที่สัมพันธ์กับ A และงานของสองส่วนนี้
- ตรวจผลต่อ foundation แล้วเสนอขอบเขตเพิ่มและ version ให้เจ้าของอนุมัติก่อนสร้างหรือแก้ UI ใน Pencil
- ขอบเขตที่ต้องกำหนดใน brief: การจัดลำดับเนื้อหา จำนวนรายการที่มองเห็น การนำทางบทความ เครดิตผู้สร้าง การหยุดคลิปเมื่อออกจากบริบท และกรณีเนื้อหาไม่พร้อม โดยไม่ขยายเป็น backend/CMS
- งานหน้าอ่านบทความเต็ม การผูกคลิปกับบ้านที่จองได้ การเชื่อม TikTok จริง และระบบจัดการเนื้อหายังไม่ได้รับอนุมัติจากการตอบคำถามเหล่านี้
