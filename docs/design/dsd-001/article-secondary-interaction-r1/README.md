# Article-secondary-interaction-r1

5 พฤศจิกายน 2026 · เรื่องรองและลิงก์บทความทั้งหมด · รอตรวจ

หลังเจ้าของรับ [featured press-r4](../article-press-r4/owner-press-acceptance.json) จึงปรับใช้สีเข้มและจังหวะเดียวกันกับอีกสอง target ตามแผนเดิม ไม่ยกการรับเรื่องเด่นเป็นการรับตัวอย่างนี้อัตโนมัติ

เรื่องรองคงรูป 208×117, ระยะ 24px และความกว้างข้อความ 360px ตามต้นฉบับ เมื่อเลือกหรือกด พื้น Navy แผ่เฉพาะพื้นที่ข้อความ ชื่อ/หมวดขาว เนื้อหา Light Blue และลิงก์อ่าน Pink พื้นขยายออกจากเนื้อหา 12px และโค้ง 16px โดยไม่ทำให้ข้อความ reflow หรือดันรูป ไม่ซูมรูป ไม่เพิ่มการ์ดถาวรในภาพปกติ

ลิงก์บทความทั้งหมดคงความสูง 44px และตำแหน่งข้อความเดิม พื้น Navy ขยายออกด้านละ 12px มุม 12px ใช้ตัวอักษรขาวและลูกศร Pink เฉพาะสถานะเลือก/กด เป็นลิงก์เดิม ไม่มีปุ่มหรือ Tab stop ซ้ำ

ทั้งสอง target ใช้สีแผ่จากตำแหน่งคลิกจริง วงครอบคลุมถึงมุมไกลสุดและคลิปภายในผิวข้อความ สีและเด้ง +3/-4/0px เริ่มพร้อมกัน 420ms easing cubic-bezier(.22,1,.36,1) แล้วถึงจังหวะเปิดปลายทาง ตัวอย่างคงภาพไว้ ไม่มี navigation จริง คง press entry 140ms และ supporting hover r8: ข้อความขวา 3px/เส้นใต้ชมพู/ลูกศรขวา 2px ขึ้น 2px ภายใน 336ms

Keyboard focus ใช้ผิวเข้มที่เลือกผ่านชั้นสีพร้อมข้อความเดียวกัน ไม่ใช้กรอบล้อมทั้งการ์ด ลำดับในตัวอย่างเป็นลิงก์ทั้งหมดแล้วเรื่องรอง แต่ละลิงก์เป็น Tab stop เดียว Enter ใช้จุดกลาง หากเข้มอยู่แล้วคงสีและเด้งต่อ เมื่อ reduced motion เปลี่ยนปลายทางสีทันที ไม่ขยับและไม่เพิ่มเวลารอนำทาง ในงานพัฒนาภายหลังต้องคง modifier/new-tab ตาม browser ปกติ ตัวอย่างกั้นลิงก์เพื่อไม่เปิดปลายทาง

Native board `lnXuU` วางสองตัวอย่างแยกกันเพื่อเทียบ endpoint ไม่แสดงสอง focus พร้อมกันใน Home [ภาพ](lnXuU.png) · [Snapshot](editable-snapshot.json) · [Bounds](bounds-diagnostics.json) ภาพ native เปิดดูครบ รูป ข้อความ และพื้นสีไม่ถูกตัดที่เห็นในภาพ แต่ Get ยังรายงานส่วนพื้นขยายว่า clipped แม้ตั้ง parent clip:false แล้ว จึงเก็บ diagnostics ไม่รับรองว่า bounds สะอาด และไม่เปลี่ยนแบบที่แสดงถูกเพื่อไล่ผลเครื่องมือ
