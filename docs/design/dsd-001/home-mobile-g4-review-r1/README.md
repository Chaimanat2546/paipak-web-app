# หน้าแรกมือถือ · แบบสำหรับตรวจ G4

11 พฤศจิกายน 2026 · เจ้าของอนุมัติภาพหน้าเต็มทั้ง 390 และ 360 พิกเซลแล้ว [บันทึกการอนุมัติ](owner-acceptance.json)

| ขนาด | ภาพเต็มหน้า | ขนาดภาพ |
| --- | --- | --- |
| มือถือหลัก 390 พิกเซล | [เปิดภาพ](dKjHl.png) | 390 × 4342 |
| มือถือจอแคบ 360 พิกเซล | [เปิดภาพ](Wm7px.png) | 360 × 4176 |

ใน [ไฟล์ Pencil](../papaipak-ui.pen) ค้นหาเฟรม **หน้าแรก · มือถือ 390 พิกเซล · ชุดตรวจ G4** และ **หน้าแรก · มือถือ 360 พิกเซล · ชุดตรวจ G4** แบบทั้งสองใช้ Header และ Footer r1 ช่องค้นหาและแถวบ้านปรับตามพื้นที่จอ ส่วนภาพเปิด TikTok บทความ และคำถามที่พบบ่อยใช้ภาพอ้างอิงหน้าแรกมือถือที่เคยรับไว้ ปุ่มค้นหาและปุ่มใต้ TikTok ใช้คู่สีปุ่มล่าสุดที่รับแล้ว

## จุดที่ใช้ตรวจรับ

- **ค้นหา** ช่องสถานที่ วันเข้าพัก และผู้เข้าพักอ่านได้ทั้งสองขนาด กติกาวันเข้าอย่างเดียวและกรณีไม่เลือกสถานที่ดูจาก [ชุดสถานะค้นหาบนมือถือ](../home-auth-feature-review-r1/uCiqX.png)
- **ทางลัดหมวด** ภาพหน้าเต็มใช้ตัวอย่างแปดหมวดพอดี มีภาพเทียบกรณีเกินแปดหมวดและปัดถึงช่อง **หมวดอื่น ๆ** ใน [ชุดแบบทางลัดที่อนุมัติแล้ว](../../admin-category-g4-r1/README.md#เปิดตรวจภาพ)
- **แถวบ้าน** ใช้ตัวอย่างสามหมวดที่เปิดแถวบ้านไว้ เห็นการ์ดแรกเต็มใบและส่วนต้นของการ์ดถัดไป แต่ละแถวมีทางเข้า **ดูทั้งหมด** ข้อมูลบ้านและราคาเป็นตัวอย่างสำหรับตรวจแบบ

ตรวจภาพและขอบเขตของส่วนหลักทั้งสองขนาดใน Pencil แล้ว การปัด การค้นหา การเล่นสื่อ และการเข้าถึงจริงอยู่ในรอบทดสอบหน้าใช้งาน

## ขอบเขตตรวจหน้าแรก G4 รอบสุดท้าย

| ความกว้าง | ภาพและจุดตรวจ |
| --- | --- |
| 1440 พิกเซล | ตรวจเดสก์ท็อปรุ่นล่าสุดเต็มหน้า เทียบลำดับส่วนต่าง ๆ กับ r20 ที่รับแล้ว ตรวจ Header, Footer, สีปุ่มล่าสุด และทางลัดหมวดในบริบทหน้าเต็ม [แบบเดสก์ท็อปล่าสุด](../pink-button-rollout-r1/Se2QH.png) · [แบบ r20 ที่รับแล้ว](../footer-contact-r5/ZRyFB.png) |
| 1280 พิกเซล | ตรวจว่าโลโก้ เมนู และปุ่มใน Header มีพื้นที่พอ ช่องค้นหาและแถวบ้านอ่านได้ครบ ใช้สี่การ์ดเป็นจุดเริ่มต้นสำหรับเทียบขนาด [แนวทาง Responsive](../responsive-visual-guidelines.md) |
| 1024 พิกเซล | ตรวจจุดเปลี่ยนของเมนูและช่องค้นหา ความกว้างของทางลัดหมวด และจำนวนการ์ดที่อ่านชื่อ ราคา และข้อมูลบ้านได้ครบ |
| 768 พิกเซล | ตรวจการจัดเรียงเมนูและช่องค้นหาในพื้นที่แคบ ทางเข้ารายการหมวด ขนาดพื้นที่กด และลำดับเนื้อหาลงมาถึง Footer |
| 390 และ 360 พิกเซล | ใช้ภาพมือถือที่อนุมัติแล้วด้านบนเทียบความต่อเนื่องของลำดับเนื้อหาและพฤติกรรมหลัก |

ภาพแต่ละขนาดใช้ตรวจว่าช่องค้นหา ทางลัดหมวด การ์ดบ้าน และปุ่มหลักอยู่ในพื้นที่ที่อ่านและเข้าถึงได้ ให้ระบุจุดเปลี่ยนตามพื้นที่ที่ตรวจพบ พร้อมภาพประกอบเฉพาะสถานะที่ช่วยอธิบายการเปลี่ยนแปลง

- **ค้นหาและดูบ้าน** เปิดหน้าแรกแล้วดูบ้านได้ทันที และค้นหาด้วยวันเข้าอย่างเดียวได้ [กติกาค้นหาที่อนุมัติ](../search-checkin-only-home-r20-r1/owner-rule-change.json)
- **หมวดและแถวบ้าน** เทียบกรณีแปดหมวดพอดีกับเกินแปดหมวด โดยกรณีเกินให้ช่องท้ายเป็น **หมวดอื่น ๆ** และตรวจว่าแต่ละแถวแสดงบ้านตามลำดับที่กำหนดพร้อมทางเข้า **ดูทั้งหมด** [ชุดแบบหมวดที่อนุมัติ](../../admin-category-g4-r1/README.md)
- **โหลดรายการบ้าน** แนบภาพโหลดครั้งแรกและกรณีโหลดไม่ได้ โดยให้ยังเห็นช่องค้นหาและทางลัดหมวดตามสเปก [สถานะหน้าแรก](../home-auth-feature-review-r1/README.md)

ชุดส่งตรวจประกอบด้วยภาพเต็มหน้า 1440, 1280, 1024 และ 768 พิกเซล ภาพมือถือที่อนุมัติแล้ว และตารางผลตรวจพร้อมจุดค้าง เจ้าของตรวจรับหน้าแรกทั้งชุดก่อนบันทึกปิด G4 ส่วนการใช้งานจริงอยู่ในรอบทดสอบ [เกณฑ์ตรวจแบบ](../../governance/04-design-quality-standards.md)
