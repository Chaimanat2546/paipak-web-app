# Article-focus-r3

5 พฤศจิกายน 2026 · เจ้าของเลือกพื้นข้อมูลเข้มและให้ค่อย ๆ เปลี่ยนสี

เจ้าของเลือกแบบ 3 จาก Article-focus-r2 พร้อมระบุ “แต่เป็นแบบค่อยค่อยเปลี่ยนสีนะไม่ใช่แบบพึบพับ” รับเป็นการเลือกหน้าตาปลายทางพื้น Navy ชื่อและหมวดสีขาว เนื้อหา Light Blue วงลูกศร Pink พร้อมลูกศร Navy ดู [คำเลือก](owner-focus-choice.json)

ตัวอย่างนี้เสนอการเปลี่ยนสีพื้น ข้อความ และวงลูกศรแบบต่อเนื่อง 500ms ease-in-out ทั้งเข้าและออก ไม่มี delay ไม่มี loop และไม่ทำให้ layout ขยับ เวลาตัวเลขนี้เป็นข้อเสนอของผู้จัดทำ ยังรอเจ้าของตรวจจังหวะ แสดงเมื่อใช้ keyboard focus หรือกดปุ่มทดลองเท่านั้น ไม่เพิ่มสีเข้มให้ hover ของเมาส์โดยอัตโนมัติ

คง featured hover r7 ที่รับแล้ว และ press r3 ที่รับแล้วตามระยะ +3/-4/0px, release 420ms, press entry 140ms ไม่แก้ source ที่รับไว้ ตัวอย่างนี้ยังไม่เปิดหน้าอ่านจริง และการนำทางในงานพัฒนาภายหลังต้องไม่รอ animation จบ หากผู้ใช้ลดการเคลื่อนไหวจะเปลี่ยนสีทันทีและหยุดการขยับ

Native root `qV3Kf` คงภาพปลายทางเดิม บันทึกชื่อ/context ให้ตรงการเลือกใหม่ ภาพนิ่งไม่พิสูจน์จังหวะ 500ms ตัวอย่างเคลื่อนไหวแยกอยู่ในแชต [ภาพ](qV3Kf.png) · [Snapshot](editable-snapshot.json) · [Manifest](review-manifest.json)

ตรวจ script syntax และ source ขนาด/asset/ค่า timing แล้ว เปิด native PNG ตรวจปลายทางแล้ว ยังไม่ทดสอบ browser interaction, font loading, keyboard/screen reader หรือคอนทราสต์ของทุกเฟรมระหว่างเปลี่ยนสี จึงยังไม่รับรอง WCAG ทั้ง treatment จาก contrast ของสีปลายทางเพียงอย่างเดียว

ขอบเขตปัจจุบันเป็นเรื่องเด่น เรื่องรองและลิงก์บทความทั้งหมดต้องปรับใช้ตามแนวที่เลือกและตรวจความสอดคล้องก่อนรวมงาน ไม่ถือว่าอนุมัติบทความ/Home/foundation ทั้งชุด ไม่เริ่ม Frontend/backend/deploy Main Home, variables และ approved sources ไม่เปลี่ยน Mobile พัก OPEN-001 เปิด

คำขอล่าสุดให้สีเริ่มจากจุดกดและจบพร้อมเด้งก่อนเปิดหน้า ดู [Article-press-r4](../article-press-r4/README.md) ข้อเสนอ 500ms และ no-wait navigation ด้านบนเป็นประวัติ ไม่ใช่แนวล่าสุด
