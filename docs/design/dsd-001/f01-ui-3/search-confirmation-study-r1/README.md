## ข้อพิจารณา

“บันทึก” สื่อการเก็บข้อมูลถาวรได้ ทั้งที่จุดนี้เป็นเงื่อนไขค้นหา อีกทั้งปุ่มชมพูในแผงมีน้ำหนักแข่งกับ “ค้นหา” นอกแผง จึงควรตัดสินหน้าที่ของปุ่มก่อนเปลี่ยนเพียงชื่อหรือสี

| แบบ | สิ่งที่เสนอ | ข้อแลกเปลี่ยน |
| --- | --- | --- |
| A: เสร็จสิ้น | ยืนยันค่าและปิดแผง ไม่ส่ง Search | เข้าใจว่าเลือกจบแล้ว แต่ยังต้องกดสองขั้น |
| B: ใช้จำนวนนี้ / ใช้วันที่นี้ | ยืนยันค่าตามชนิดของ field แล้วปิดแผง | ชัดกว่าบันทึก แต่ยังมี confirmation ก่อน Search |
| C: ไม่มีปุ่มบันทึก (แนะนำ) | แก้ค่าแล้วแสดงใน search form ทันที ปิดด้วย X, outside click หรือไปช่องถัดไปโดยค่าคงอยู่; ส่งคำค้นเมื่อกด Search เท่านั้น | ลดหนึ่งขั้น แต่เปลี่ยนกติกาการเก็บค่าระหว่างเปิด/ปิดแผง จึงต้องให้เจ้าของเลือกก่อนนำไปปรับจริง |

ภาพใช้ counter 12 คน / 1 pet เหมือนกัน เพื่อเทียบหน้าที่ของ confirmation ไม่ใช่ตัวเลขหรือสไตล์อื่น ทั้งสามคง Mitr, navy/light blue/pink และ Search CTA เดิม ไม่ปิด OPEN-001

ถ้าเลือก C สำหรับวันที่: เลือกวันออกครบแล้วใช้ช่วงวันใน form และปิดแผง; ถ้าปิดขณะเลือกไม่ครบให้คงสถานะ draft ที่อ่านได้ กด Search แล้วเข้าสู่ error/recovery เดิม ไม่ส่งช่วงวันที่ไม่ครบและไม่ล้าง field อื่นโดยเงียบ ๆ สัตว์เลี้ยงแยกจากคนรวมตามกฎเดิม

C ไม่ทำให้รายการ Results เปลี่ยนตามทุกครั้งที่กด counter ค่าใน search form กับผลค้นหาที่ส่งแล้วเป็นคนละสถานะ ยังไม่เปลี่ยน Filter Apply behavior และไม่สรุป D-02 ของ booking date editor จากข้อเสนอนี้

## หลักฐานและสถานะตรวจ

อ้างอิง UI ที่ตรวจจริงใน [Search-states-r4](../search-states-r4/README.md) กับตัวอย่าง Airbnb ที่ศึกษาไว้แล้ว ไม่เพิ่มคำอ้างว่าเว็บไซต์อ้างอิงใช้ C ทุกกรณี

สร้างเป็น native editable board แยกจากต้นฉบับ ตรวจ PNG เต็มขนาดและ native bounds แล้ว ไม่มี clipping ใน read-back สุดท้าย รายการ warnings ตอนสร้างเป็น transient layout pass; snapshot หลัง layout settle ไม่พบปัญหา ไม่มี runtime click/keyboard test หรือการเปลี่ยน behavior จริง

ภาพนี้ให้เลือกแนวทางก่อนใช้กับ date/guest states บน Home/Results ทั้งชุด A/B/C ยังไม่มีตัวใดได้รับอนุมัติ
