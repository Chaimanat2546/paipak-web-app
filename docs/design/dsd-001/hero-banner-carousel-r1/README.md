ภาพแรกใช้ภาพและข้อความเดิมรวมเป็น raster ส่วนภาพที่สอง/สามใช้ภาพศึกษาจากการ์ดเดิมและข้อความชุดเดียวกัน มีแผ่นขาวไล่โปร่งใน artwork เพื่อให้อ่านได้ ทุกอย่างรวมในภาพก่อนใช้ใน Hero ไม่ใช่ข้อความหรือ scrim ที่เว็บวางซ้ำบนสไลด์ โฟลเดอร์ [banner-assets](banner-assets) เก็บไฟล์สำเร็จรูปทั้งสาม ไม่มีภาพจริง/สิทธิ์ใช้จริงที่รับรองจากร่างนี้

Hero ใน Home รุ่นใหม่มีภาพ raster หนึ่งชิ้นที่แสดงอยู่ ไม่มีหัวเรื่องหรือคำโปรยเป็น text node ทับภาพอีก ส่วนข้อความ Search ยังเป็น text node ตามหน้าที่ ขอบสระเป็น mask ของหน้าและ Search เป็นชั้นคงที่ แยกจากภาพที่เลื่อน

## Controls ที่เสนอให้ตรวจ

- ลูกศรขาว/ไอคอน Navy ด้านซ้ายและขวา ขนาด44×44px
- จุดเลือกสามภาพอยู่ใต้ Search ใช้ capsule Navy แสดงภาพที่เลือก จุดอื่นสงบลง; พื้นที่กด44×44pxต่อจุด
- ปุ่มพักข้างจุดเลือก ขนาด44×44px; สถานะพักแสดงไอคอนเล่นต่อ
- ภาพทั้งหมดไม่มีลิงก์ หน้าตา/ตำแหน่ง controls นี้ยังรอเจ้าของเลือก ไม่อ้างว่าผ่านเพียงเพราะยืนยันพฤติกรรม carousel แล้ว

## การตรวจและข้อจำกัด

ตรวจภาพ native และ PNG บริบทภาพแรกแบบเต็ม1440pxแล้ว ไม่พบการบังหัวเรื่องโดย controls ในภาพที่ตรวจ Search กับขอบสระตรงกับต้นฉบับโดยเปรียบเทียบ schema ยกเว้น IDs อีก11ส่วนของ Home ตรงกันทั้งหมด ดู [preservation-audit](preservation-audit.json) Variables ตรงกับค่าที่อ่านก่อนแก้ ไม่มี SetVariables

Diagnostics ยังแจ้ง fully clipped ที่ controls บางชิ้นใน root ทั้งหน้า แม้เห็นครบในภาพที่ส่งออก และอีก7รายการเป็น listing tracks เกิน viewport ตามฐานเดิม บันทึก [geometry](geometry-observations.json) ไว้ ไม่อ้างว่า diagnostics สะอาด ไม่ขยับตำแหน่งที่เห็นถูกต้องเพื่อไล่รายงานดังกล่าว

แบบนี้เป็น static states: ยังไม่มี carousel ที่กด/เลื่อนอัตโนมัติจริง ไม่มีการทดสอบ7วินาที keyboard/screen reader/reduced motion หรือการพัก/เล่นต่อ ปุ่มพักเป็นข้อเสนอเพื่อควบคุม autoplay ระยะเวลา/easing และนโยบายเริ่มนับใหม่ยังไม่เลือก กรณี0/1ภาพ โหลด/ล้มเหลวยังไม่ได้เพิ่มแบบ ไม่ถือว่าชุด states ครบทั้งหมด
