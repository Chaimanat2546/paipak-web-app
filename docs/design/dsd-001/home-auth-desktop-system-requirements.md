# Home Auth Desktop · ข้อกำหนดระบบ

10 พฤศจิกายน 2026 · DSD-001 / C2 · ขอบเขต Home Desktop

เอกสารนี้เติมกติกาที่เจ้าของเลือกหลังรับ [Wireframe G2-r40](home-auth-consolidated-g2-r40/owner-G2-r40-acceptance.json) และ [Interaction Contract](home-auth-interaction-contract.md) ค่าที่ระบุในเอกสารนี้ให้ใช้เหนือค่าตัวอย่างในภาพและรายการที่เคยรอสรุปใน G2

ค่าตัวเลขและคำตอบเรื่องบัญชีมาจาก [papaipak-auth-decisions · คำถามระบบจริง A6:E24](https://docs.google.com/spreadsheets/d/1LgD1thUvgahT-irKCGLCnViqBopjfG26PpO3HkF3l_0/edit#gid=10638671&range=A6:E24) ห้ารายการที่ยังเขียนว่า “เสนอได้” ในชีต (OTP-06, ACC-02 และ ERR-01 ถึง ERR-03) ใช้ข้อเสนอที่เจ้าของยืนยันภายหลังว่า “โอเค เอาตามที่คุณว่าได้เลย” พร้อมกำหนดให้บันทึกเป็นข้อกำหนดเท่านั้น

## สิ่งที่ใช้จาก Wireframe G2-r40

- เข้าใช้ด้วย OTP ทางอีเมลเป็นหลัก มีรหัสผ่านเป็นทางเลือกสำหรับอีเมล ใช้เบอร์โทรคู่กับรหัสผ่านได้ และมี Google การสมัครด้วยอีเมลต้องตั้งรหัสผ่านอย่างน้อย 8 ตัวและยืนยันให้ตรงกัน ส่วนการยืนยันอีเมลหลังสมัครทำทีหลังได้
- ใช้ OTP 6 ช่องและตรวจอัตโนมัติเมื่อครบ ใช้ตัวนับในปุ่มส่งซ้ำ รวมถึงสถานะกำลังส่ง กำลังตรวจ รหัสผิด รหัสหมดอายุ ส่งไม่สำเร็จ และตรวจไม่สำเร็จตาม [รายการสถานะ G2-r40](home-auth-consolidated-g2-r40/inventory.md) ค่า `00:45` ในภาพเป็นตัวอย่างการแสดงผล
- Google ใช้สถานะกลับจากการยกเลิกและข้อผิดพลาดเดิม ผู้สมัครผ่าน Google เข้าใช้ได้โดยไม่ต้องยืนยันอีเมลกับเว็บอีก [ข้อสรุปเรื่อง Google](home-auth-google-no-extra-email-verification.json)
- การปิด modal ล้างข้อมูลในฟอร์ม Auth เมื่อเปิดใหม่ โดยคืนหน้า Home ตามสถานะค้นหา การเลื่อนหน้า แถวรายการ และรูปที่ยังอยู่ตามสัญญาเดิม ข้อผิดพลาดที่ระบุช่องได้แสดงใต้ช่องนั้น ส่วนข้อผิดพลาดที่ระบุช่องไม่ได้แสดงระดับฟอร์ม
- ใช้สถานะกำลังบันทึกและบันทึกแล้วของรายการโปรดตาม [G2-r28](home-auth-favorite-return-g2-r28/owner-favorite-return-states-acceptance.json) เส้นทางเชื่อม Google เมื่ออีเมลตรงกับบัญชีเดิมต้องมีขั้นยืนยันเพิ่มจาก G2-r40

## กติกา OTP และบัญชี

| อ้างอิง | ข้อกำหนดที่ยืนยันแล้ว |
| --- | --- |
| OTP-01 | OTP ทางอีเมลมีอายุ 5 นาที ใช้ทั้งตอนเข้าใช้และตอนยืนยันอีเมลหลังสมัครในเว็บ |
| OTP-02 | รอ 60 วินาทีก่อนส่งรหัสซ้ำ แสดงเวลาที่เหลือในปุ่มส่งซ้ำ |
| OTP-03 | จำกัดการขอ OTP ที่ 10 ครั้งใน 1 ชั่วโมง |
| OTP-04 | จำกัดการกรอก OTP ผิดที่ 20 ครั้งใน 1 ชั่วโมง จากนั้นต้องรอก่อนลองอีกครั้ง ระยะเวลาที่ต้องรอยังรอสรุป |
| OTP-05 | เมื่อระบบยืนยันว่าออกรหัสใหม่สำเร็จ รหัสก่อนหน้าใช้ไม่ได้ ถ้าส่งไม่สำเร็จหรือยังไม่ทราบผล ให้ยึดสถานะจริงของรหัสเดิมและอายุของรหัส |
| OTP-06 | เมื่ออีเมลมาช้าหรือยังมาไม่ถึง ให้ตรวจอีเมลที่กรอกและโฟลเดอร์สแปม ใช้ปุ่มส่งซ้ำเดิมเมื่อรอครบ 60 วินาที เมื่อออกรหัสใหม่สำเร็จให้ใช้รหัสชุดล่าสุด ถ้าระบบยืนยันการส่งล้มเหลว ให้ใช้สถานะส่งไม่สำเร็จเดิม สำหรับการยืนยันหลังสมัคร ให้ตรวจที่อยู่อีเมลบัญชีที่แสดงในขั้นนั้น |
| ACC-01 | ถ้าอีเมลหรือเบอร์โทรที่ใช้สมัครมีบัญชีอยู่แล้ว ให้ระบุข้อผิดพลาดใต้ช่องที่เกี่ยวข้องและพากลับไปเข้าใช้บัญชีเดิม |
| ACC-02 | ถ้า Google ส่งอีเมลตรงกับบัญชีเดิมที่ยังไม่ได้เชื่อม ให้ยืนยันสิทธิ์ในบัญชีเดิมและขอความยินยอมก่อนเชื่อม บันทึกการเชื่อมด้วยรหัสประจำบัญชี Google ที่คงที่ การตรงกันของอีเมลอย่างเดียวใช้เชื่อมบัญชีไม่ได้ |
| ACC-03 | คำตอบในชีตคือ `th en usa` ยืนยันไทยและสหรัฐฯ ได้ ความหมายของ `en` และรายชื่อประเทศครบชุดยังรอสรุป ชื่อตัวเลือกไทยใช้ “ไทย” ส่วนประเทศอื่นใช้ชื่อภาษาอังกฤษตาม G2 |
| ACC-04 | บัญชีอ้างอิงอีเมล เบอร์โทรใช้แทนอีเมลสำหรับเข้าใช้ด้วยรหัสผ่านของบัญชีเดียวกัน การกู้รหัสส่งลิงก์ไปยังอีเมลของบัญชี |

## การกู้รหัสผ่านและเซสชัน

| อ้างอิง | ข้อกำหนดที่ยืนยันแล้ว |
| --- | --- |

| REC-03 | เจ้าของระบุ “10 รอ 1 ชม” สำหรับโควตาการขอลิงก์ ต้องสรุปช่วงนับและจุดเริ่มรอก่อนใช้เป็นกติกาบังคับ |

## เมื่อผลคำขอยังไม่ชัดหรือผู้ใช้ปิด modal ไปแล้ว

| อ้างอิง | ข้อกำหนดที่ยืนยันแล้ว |
| --- | --- |
| ERR-01 | เมื่อการเชื่อมต่อหลุดหลังส่งคำขอ ให้ตรวจผลคำขอเดิมก่อนสรุปหรือส่งซ้ำ ถ้าจำเป็นต้องลองซ้ำ ให้ใช้คำขอเดิมในเชิงผลลัพธ์ เพื่อให้การสมัครหรือส่ง OTP เกิดได้เพียงครั้งเดียว การกดขอรหัสใหม่โดยตั้งใจเป็นอีกคำขอและอยู่ภายใต้โควตาเดิม |
| ERR-02 | ถ้าผลเข้าใช้หรือสมัครกลับมาหลังปิด modal ให้ modal คงปิดอยู่และเปิดครั้งใหม่ด้วยฟอร์มเปล่า หน้า Home แสดงสถานะเข้าใช้ตามผลที่ยืนยันแล้ว การปิด modal ยุติการบันทึกรายการโปรดที่รอเข้าใช้ แม้ผลเข้าใช้จะสำเร็จภายหลัง การส่ง OTP สำเร็จอย่างเดียวยังไม่ถือว่าเข้าใช้สำเร็จ |
| ERR-03 | เมื่อยังไม่ทราบผลบันทึกรายการโปรด ให้ตรวจสถานะจริงของบ้านที่กดและแสดงว่าบันทึกแล้วเมื่อยืนยันผลได้ บ้านที่บันทึกอยู่แล้วต้องคงสถานะเดิม ให้ทำต่ออัตโนมัติเฉพาะคำขอบันทึกที่ยังอยู่ในขั้นเข้าใช้ต่อเนื่อง ใช้สถานะ r28 ที่รับไว้ และคงผล [การปฏิเสธสถานะ r29](home-auth-favorite-result-g2-r29/owner-not-needed-rejection.json) สำหรับข้อความและปุ่มตรวจผลหรือกดซ้ำ |

## ทางเดินเมื่ออีเมล Google ตรงกับบัญชีเดิม

การยืนยันบัญชีเดิมและขอความยินยอมก่อนเชื่อมเป็นข้อกำหนดที่เจ้าของเลือกแล้ว ดู [Wireframe G2-r41 ที่รับแล้ว](home-auth-google-link-g2-r41/README.md) และ [หน้าตา Google Link G3-r3 ที่รับแล้ว](home-auth-google-link-g3-r3/README.md) วิธีที่ใช้ยืนยันสิทธิ์จริงยังอยู่ในรายการข้อกำหนดที่ต้องสรุป

1. ผู้ใช้เริ่มจาก Google ใน Login หรือ Register ถ้าบัญชี Google เชื่อมไว้แล้ว ให้เข้าใช้ด้วยข้อมูลที่เชื่อมอยู่ ถ้าเป็นบัญชีใหม่ที่ไม่ชนบัญชีเดิม ให้ใช้ทางเดินสมัครด้วย Google ที่รับไว้
2. ถ้าอีเมลตรงกับบัญชีเดิมที่ยังไม่ได้เชื่อม ให้อธิบายว่าต้องยืนยันบัญชี papaipak เดิมก่อน และให้เลือกวิธีที่บัญชีเดิมใช้ได้ การเข้าขั้นนี้อย่างเดียวจะไม่ส่ง OTP
3. เมื่อยืนยันบัญชีเดิมสำเร็จ ให้มีขั้นยืนยันหรือยกเลิกการเชื่อมแยกต่างหาก เชื่อมต่อเมื่อผู้ใช้ยืนยัน และใช้ผลที่ตรวจสอบได้ก่อนจบขั้นนี้

| เหตุการณ์ | ผลที่เสนอให้ใช้ใน Wireframe |
| --- | --- |
| ยืนยันและเชื่อมสำเร็จ | จบการเข้าใช้และกลับจุดเดิมบน Home ทำรายการโปรดต่อได้เฉพาะเมื่อคำขอบันทึกเดิมยังอยู่ในขั้นเข้าใช้ต่อเนื่อง |
| ยกเลิกขั้นเชื่อม | กลับ Login หรือ Register ที่เริ่มมา รักษาข้อมูลที่ยังอยู่ในฟอร์มเดิมและไม่ขอ OTP เอง ถ้าปิดทั้ง modal ให้ล้างฟอร์มและคืน Home ตาม G2 |
| ยืนยันบัญชีเดิมไม่สำเร็จ | อยู่ในขั้นยืนยัน แสดงข้อผิดพลาดใต้ช่องเมื่อระบุช่องได้ หรือก่อนปุ่มหลักเมื่อเป็นข้อผิดพลาดระดับฟอร์ม |
| เชื่อมไม่สำเร็จหรือยังไม่ทราบผล | อยู่ในขั้นเชื่อม ถ้ายืนยันว่าล้มเหลวแล้วให้แจ้งที่ระดับฟอร์มและลองใหม่ได้เมื่อปลอดภัย ถ้ายังไม่ทราบผลให้ตรวจผลเดิมก่อน |

## เรื่องที่ยังต้องตัดสินใจ

- OTP และลิงก์กู้รหัสผ่านต้องกำหนดจุดเริ่มนับเวลา วิธีนับและแบ่งโควตาระหว่างวัตถุประสงค์ ระยะพักหลังกรอกผิด และความหมายเชิงกติกาของ `10 รอ 1 ชม`
- เบอร์โทรต้องยืนยันความหมายของ `en` รายชื่อประเทศที่รองรับ วิธีแปลงและตรวจรูปแบบเบอร์ และกติกาจับคู่บัญชี รวมถึงทางกู้บัญชีเมื่อผู้ใช้เข้าถึงอีเมลเดิมไม่ได้
- การเชื่อม Google ต้องยืนยันว่าวิธีใดใช้พิสูจน์สิทธิ์ในบัญชีเดิมได้เมื่อเกิดการชนกัน อายุของขั้นยืนยัน และข้อความกับทางกลับที่จะใช้จริง
- เซสชันต้องนิยามกิจกรรมที่ต่ออายุ อายุต่อเนื่องสูงสุดถ้ามี และอุปกรณ์ที่ต้องเข้าใช้ใหม่หลังตั้งรหัสผ่าน ตำแหน่งและระยะเวลาแสดงผลบันทึกรายการโปรดยังรอตรวจในแบบเต็มหน้า

## เกณฑ์ตรวจรับข้อกำหนด

- ครอบคลุม OTP ทั้งเข้าใช้และยืนยันหลังสมัคร โดยใช้ 5 นาที, 60 วินาที, 10 ครั้งต่อชั่วโมง และ 20 ครั้งต่อชั่วโมงตรงตามรายการ และแยกผลของการส่งรหัสใหม่สำเร็จ ล้มเหลว และยังไม่ทราบผลได้
- แยกกรณีอีเมลหรือเบอร์ซ้ำตอนสมัคร บัญชี Google ที่เชื่อมแล้ว บัญชีใหม่ และอีเมล Google ที่ตรงกับบัญชีเดิม กรณีสุดท้ายต้องผ่านการยืนยันสิทธิ์และการยินยอมก่อนเชื่อม
- แยกลิงก์กู้รหัสที่ยังมีอายุออกจากลิงก์หมดอายุหรือถูกยกเลิกหลังตั้งรหัสใหม่ และแสดงกติกาเซสชัน 3 วันที่ไม่มีกิจกรรมโดยยังเก็บประเด็นขอบเขตอุปกรณ์ไว้ให้ตัดสินใจ
- ตรวจเส้นทางกรณีหลุดหลังส่งคำขอ ผลกลับมาหลังปิด modal และผลบันทึกบ้านที่ยังไม่ทราบได้ โดยไม่มีผลซ้ำ ไม่มีการเปิดฟอร์มเดิมกลับมา และไม่มีสถานะบันทึกแล้วก่อนผลยืนยัน
