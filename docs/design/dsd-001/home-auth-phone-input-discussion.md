# รูปแบบเบอร์ที่ผู้ใช้กรอกหรือคัดลอกมา

DSD-001/C2 · 5 พฤศจิกายน 2026 · เจ้าของเลือกข้อ1แล้วตาม [บันทึก](home-auth-phone-input-decision.json); ตัวเลือกด้านล่างเป็นประวัติ

คงcountry selector/ไทยเริ่ม+66, ชื่อประเทศและ [shared Login phone presentation-r34](home-auth-login-country-g2-r34/owner-Login-country-acceptance.json) ที่รับแล้ว เบอร์ยังใช้password ไม่มีSMS ไม่เปิดเลือกประเทศ/วิธีLoginใหม่

รูปแบบเบอร์/normalizationเคยถูกระบุเป็นcontractที่ยังเปิด จึงต้องแยกสิ่งที่ผู้ใช้กรอกได้ออกจากจำนวนหลัก/การจับคู่บัญชี/providerจริง คำถามนี้ใช้กับเบอร์ในRegisterและphone-stateของLoginร่วมอีเมล/โทร ไม่เปลี่ยนemail parsing

1. เสนอรับทั้งเบอร์ปกติและเบอร์พร้อม+รหัสประเทศ รวมการเว้นวรรค/ขีดที่ใช้จัดเบอร์ แล้วจัดรูปแบบส่วนcode/หมายเลขให้ไม่ซ้ำกัน เหมาะกับการคัดลอกเบอร์มา คำแนะนำเอเจนต์ ยังไม่ใช่คำตัดสิน
2. รับเบอร์ปกติภายในประเทศที่เลือก รวมเว้นวรรค/ขีด แต่ไม่รับ+รหัสประเทศซ้ำในช่องหมายเลข ใช้ตัวเลือกประเทศเป็นแหล่งcodeเพียงจุดเดียว
3. รับเฉพาะตัวเลขของเบอร์ภายในประเทศที่เลือก ไม่รับเว้นวรรค/ขีด/+ กำหนดรูปแบบกรอกตายตัว

ตัวอย่าง081…และ+66…เป็นตัวอย่างวิธีเขียน ไม่ใช่pattern/ความยาวที่ระบบจริงตรวจผ่านแล้ว หากเลือกแบบยืดหยุ่น การปรับประเทศจากexplicit+prefixต้องแยกจากการเดาประเทศด้วยเลขภายใน และไม่เลือกประเทศผิดเงียบๆเมื่อcodeเดียวสัมพันธ์ได้หลายประเทศ จะระบุหลักการยืนยันผลและกรณีไม่ชัดในcontractก่อนimplementation ไม่ใช้คำถามนี้เลือกAPI/library/providerหรือรายการประเทศทั้งหมด

เจ้าของเลือกinputแบบยืดหยุ่นแล้วตามบันทึกข้างต้น แต่ไม่ได้เลือกprovider/จำนวนหลักหรือnormalization implementation ไม่ส่งOTP/Authเองจากการจัดรูปแบบ ไม่จำข้อมูลข้ามปิดAuth/reload และไม่อนุมานการยืนยันเจ้าของเบอร์/บัญชี ไม่มีcode/SDK/backend/FrontendหรือwholeG2 approval
