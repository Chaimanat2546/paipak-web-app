## ผลต่อฐานที่รับไว้

ข้อสรุปนี้เปลี่ยนวิธีแสดงสื่อเฉพาะ Home Hero จากภาพพื้นหลังร่วมกับข้อความเว็บ ไปเป็นภาพรวมสำเร็จรูปหลายสไลด์ สำหรับ Hero รุ่นที่จะจัดทำต่อไป ค่า `home.hero.title` 96/600 และ `home.hero.support` 22/500 ใน [typography-spec](typography-spec.md) ยังเป็นหลักฐานของ Home-r15 เดิม ไม่ใช่ข้อกำหนดให้เว็บสร้างตัวหนังสือทับภาพสำเร็จรูปใหม่

[Home Desktop-r15](home-desktop-r15/owner-home-acceptance.json) และ [foundation-3-desktop](foundation-3-desktop/owner-foundation-acceptance.json) เก็บตามเวอร์ชันที่รับไว้ ไม่อ้างว่าภาพหรือ editable source เดิมมี Hero carousel นี้แล้ว การยืนยันครั้งนี้ไม่เปลี่ยน Mitr ของข้อความเว็บส่วนอื่น สีแบรนด์ หมวด รายการบ้าน หรือ UX/business rules ที่รับไว้ Mobile ยังพักตามเดิม

## รายละเอียดที่ยังต้องจัดทำต่อ

- ระยะเวลาและ easing ของการเลื่อนแนวนอน ตำแหน่ง/หน้าตาของ controls และการพัก/เล่นต่อที่ผู้ใช้สั่งเอง
- จังหวะเริ่มนับ 7 วินาทีใหม่หลังการกดเลื่อนหรือพัก รวมถึงเมื่อกลับมาใช้งานหน้าเว็บ
- ขนาดและสัดส่วนไฟล์ การแสดงที่ความกว้าง Desktop อื่น และพื้นที่ที่ Search/controls ซ้อน เพื่อไม่ให้บังสาระสำคัญในภาพ
- กรณี0ภาพยืนยันให้ใช้ภาพปัจจุบันเป็นภาพสำรองแล้วตามr3 ไม่ใช้compact fallbackของr2 ส่วนการซ่อนcontrolsเมื่อมีภาพเดียว การข้ามภาพเสียบางส่วนและช่วงinitial-loadingยังมี [ตัวอย่างเสนอ](hero-banner-carousel-r3/README.md) ซึ่งยังไม่เท่ากับการรับcontrolsหรือทดสอบโหลดจริง
- ข้อความทดแทน/ความหมายหัวเรื่องสำหรับเทคโนโลยีช่วยอ่าน การใช้คีย์บอร์ด focus และ reduced motion ต้องออกแบบและตรวจในขอบเขต Hero นี้ ไม่ถือว่าการใช้ภาพแก้เรื่อง accessibility แล้ว
- ภาพจริงและข้อความภายในภาพยังไม่ได้ส่งตรวจ ไม่กำหนดฟอนต์ภายในไฟล์หรือรับรองสิทธิ์ใช้งานจากคำตอบนี้

## เกณฑ์ตรวจเมื่อมีแบบและต้นแบบ

1. แต่ละสไลด์ใช้ภาพรวมหนึ่งไฟล์ ไม่มีข้อความเว็บซ้ำทับตัวหนังสือในภาพ
2. เมื่อมีหลายภาพและไม่ได้พัก ภาพเลื่อนแนวนอนวนตามเวลาที่เลือก 7 วินาทีต่อภาพ และเลือกภาพด้วย controls ได้
3. วางเมาส์หรือใช้งาน Search แล้วภาพไม่เลื่อนอัตโนมัติรบกวนผู้ใช้
4. กดพื้นภาพแล้วไม่เปลี่ยนหน้า ส่วน controls และ Search ยังทำงานตามหน้าที่ การเปลี่ยนภาพไม่ล้างค่าค้นหา
5. รายละเอียดค้างด้านบนมีข้อสรุปและหลักฐานตามขอบเขต ก่อนขอรับแบบ Hero รุ่นใหม่

## การอนุญาตปรับ UI และร่างปัจจุบัน

หลังเลือกการเลื่อนแนวนอน เจ้าของระบุ “โอเคเริ่มปรับได้” จึงจัดทำ [Hero banner carousel-r1 / Home Desktop-r16](hero-banner-carousel-r1/README.md) ใน Pencil เป็นร่างตรวจหน้าตา มีภาพสำเร็จรูปตัวอย่างสามภาพ สถานะพัก และช่วงเลื่อนแนวนอนแบบภาพนิ่ง คง Search และอีก11ส่วนของ Home ตามเดิม

หน้าตา controls และ UI รุ่นนี้ยังรอเจ้าของตรวจ รายละเอียดค้างข้างต้นยังมีผล ยังไม่ใช่ carousel ที่ทำงานจริง ไม่มีการทดสอบเวลาหรือ accessibility ไม่แก้โค้ด/CSS และยังไม่ commit/push การเปลี่ยนแปลงรอบนี้

เจ้าของสั่ง “โอเคจัดการเลยแล้วก็จัดการตัว pencil ต่อ” จึงจัดสเป็กหลักทั้งสี่ให้ตรงกัน และเพิ่ม [Hero carousel-r2](hero-banner-carousel-r2/README.md) สำหรับภาพเดียว/ไม่มีภาพ/โหลด/เสียบางภาพ/เปิดSearch/hover ข้อกำหนดหลักที่ยืนยันยังเดิม ส่วนstatesใหม่เป็นข้อเสนอรอตรวจ ไม่ถือว่าคำสั่งให้ทำต่อเป็นการรับหน้าตาหรือfallback policy

ต่อมาเจ้าของยืนยันให้ใช้ภาพปัจจุบันเป็นภาพสำรองมาตรฐานเมื่อไม่มีภาพ จึงปรับเป็น [Hero carousel-r3](hero-banner-carousel-r3/README.md) คงHero/ขอบโค้งขาว/Search ไม่ใช้แถบค้นหาสั้น ภาพในPencilปรับแล้ว แต่ยังไม่มีการบรรจุfallbackassetเข้าแอปหรือทำcarouselจริง

เจ้าของตอบ “โอเคตกลงแบบนี้แหละ” รับหน้าตาfallbackที่แสดงในHZP8Rแล้ว รวมการคงภาพ/ขอบโค้งขาว/Searchและซ่อนcontrolsเมื่อเป็นภาพสำรองหนึ่งภาพ ดู [หลักฐานรับเฉพาะรุ่น](hero-banner-carousel-r3/owner-fallback-appearance-acceptance.json) ไม่รับcontrolsหลายสไลด์ initial-loading หรือHomeทั้งชุดจากคำตอบนี้
